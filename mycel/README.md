# Mycel — ローカル Markdown を、つながるノートに

Obsidian のように「ただの .md フォルダ」をリンクでつないで使うノートアプリです。
Word・Excel・PowerPoint・PDF・メールなどの資料も読み込んで、ノートと一緒に検索・グラフ・AI の対象にできます。
Python の標準ライブラリだけで動き、ブラウザで開いて使います。LLM（OpenAI 互換 API / Azure OpenAI）
を登録すると、ノートと資料に質問・要約・リンク候補などの AI 機能が使えます。

```bash
python mycel/server.py                     # http://127.0.0.1:8795
python mycel/server.py --vault D:/notes    # Vault（ノートを置くフォルダ）を指定
python mycel/server.py --port 9000 --open  # ポート変更・ブラウザを開く
```

Windows は `mycel/start.bat` をダブルクリックでも起動できます。App Portal（`launcher/`）にも登録済みです。

- pip install 不要（Python 3.10 以降）。PDF を読むときだけ `pip install pypdf`。`127.0.0.1` にだけ bind し、外部には公開しません
- 初回起動時、Vault が空ならサンプルノート（営業ナレッジの例）を入れます（`--no-sample` で無効）
- 既定の Vault は `mycel/vault/`（.gitignore 済み）。設定画面から変更できます

## できること

| 領域 | 機能 |
|------|------|
| ノート | Markdown の編集 / 閲覧切り替え（`Ctrl+E`）、自動保存、プロパティ（先頭の `---` ブロック）表示、チェックボックスをクリックで切り替え |
| リンク | `[[ノート名]]` `[[ノート名\|表示名]]` `[[ノート名#見出し]]` `[[フォルダ/ノート名]]`。`[[` で候補を補完。未作成のリンクをクリックすると新規作成 |
| バックリンク | このノートを参照しているノートと文脈、**未リンクの言及**（タイトルを含むがリンクされていない箇所。ワンクリックでリンク化） |
| 名前変更 | タイトル欄を書き換えて Enter。Vault 全体の `[[旧名]]` を自動で書き換え（同名ノートがある場合はパスで書く） |
| 検索 | 全文検索（SQLite FTS5 trigram で日本語も部分一致、`Ctrl+Shift+F`）、クイックスイッチャー（`Ctrl+K`、`>` でコマンド） |
| 整理 | `#タグ` 一覧、デイリーノート（`Ctrl+D`）、テンプレート（`{{title}}` `{{date}}` `{{time}}` `{{author}}`）、フォルダへのドラッグ移動 |
| グラフ | 現在ノートの 1〜2 ホップ／Vault 全体。フォルダごとに色分け、ドラッグ・ズーム、クリックで開く。「知識グラフ」をオンにすると GraphRAG で抽出した実体（六角形）と実体同士の関係を重ねて表示し、実体をクリックすると登場する文書の一覧から文書同士を「つながり」として保存できる |
| AI | ノート・資料に質問（根拠付き・会話の続き可・対象をフォルダ／外部フォルダに絞れる）、要約とタグ提案、リンク候補、選択範囲の書き換え（整える／アクション抽出／メール文／自由指示） |
| GraphRAG（任意） | 質問の「方式」で選んだときだけ使う。文書から実体（人・組織・製品・概念）と関係を LLM で抜き出して知識グラフを作り、コミュニティごとに要約。**局所**（質問に出る実体から関係をたどって答える）と**全体**（コミュニティ要約を map/reduce して全体像を答える）、質問文から自動で選ぶ **自動**。既定は従来の標準方式のままで、索引は「GraphRAG の索引を作る」を押したときだけ、変わった文書分を作る |
| AI 取り込み | PDF・Word・PowerPoint などの文書をドロップすると、ローカル LLM が読んで要約・要点・登場する顧客名や人名・タグを付け、RAG で既存ノートとの関連を見つけた**つながったノートの下書き**を作る。確認・編集して保存 |
| 資料の整理 | フォルダの作成・名前変更・移動・削除、資料の名前変更・移動・削除（ドラッグ＆ドロップ可）。フォルダにファイルをドロップして資料を追加。フォルダの一覧表示でまとめて移動・削除。ファイル一覧は「すべて／ノート／資料」で切り替え |
| 文献管理モード | 論文・報告書・書籍を「文献」として登録（PDF などの資料・BibTeX/RIS・手入力）。文献の本文だけを対象にした意味検索（一致した段落つき）、文献だけを根拠にした質問、読了状態・評価・タグ、AI の構造化要約（目的・手法・結果・限界）と書誌情報の補完、引用文（APA/IEEE/BibTeX）、読書ノート。文献同士を引用・発展・支持・反論・比較などの関係でつなぐ（AI の提案、引用関係の自動検出）。分解グラフは「タグ → 文献 → 章 → 段落」とクリックで開け、内容の近い要素を別の文献の章・段落とも点線で結ぶ |
| 人物・組織 | ノート・資料に出てくる人と会社を自動で見つけ、[[リンク]] を書かなくても「同じ人が出てくる文書」としてつなぐ。人物ごとに登場する文書と立場・所属（推定）・一緒に出てくる人・名前は出ないが関係がありそうな文書を表示し、ローカル LLM で人物像を推定。誤りは文書ごとに外す・まとめる・戻すで直せる |
| つながり | 資料同士（資料とノートも）を「つながり」で結ぶ。説明（改訂版・添付など）を付けられ、グラフに点線で出る。AI が似ている資料を探して関係を判断、フォルダ内の近い資料の組をまとめて提案 |
| 資料 | 画像以外の資料を読み取り専用で表示・検索・AI の根拠に。「アプリで開く」「ダウンロード」「ノートとして取り込む」。`[[見積書.docx]]` でリンクも可 |
| 読み込み範囲 | Vault 内のフォルダを外す、Vault の外のフォルダ（共有フォルダなど）を追加、形式・サイズ上限を選ぶ。フォルダごとの読込件数・未反映・エラーを表示 |
| 更新 | 初回だけ自動で読み込み、以降は「更新」を押したときだけ**変更されたファイルだけ**を読み込む。範囲ダイアログで選んだフォルダ・ファイルだけ更新もできる |
| 外部変更 | 開いているノートを他のエディタで編集すると数秒で反映。同時に編集した場合は競合を検出して「相手の版／自分の版」を選べる |
| 履歴 | 変更ジャーナル（誰がいつ何を変えたか）。Git 履歴プラグインで自動 commit も可 |

ノートを削除すると Vault 内の `.mycel/trash/` に移動します（完全には消えません）。

## 読める形式と、読み込みの流れ

| 種類 | 拡張子 | 読み方 |
|------|--------|--------|
| ノート | `.md` `.markdown` | 編集できる。リンク・タグ・バックリンクの対象 |
| テキスト | `.txt` `.log` | 文字コードを自動判別（UTF-8 / Shift_JIS / EUC-JP） |
| 表 | `.csv` `.tsv` `.xlsx` `.xlsm` | 表として表示（シートごと。大きい表は先頭を抜粋） |
| Word / PowerPoint | `.docx` `.pptx` | 見出し・箇条書き・表を保ったテキスト（スライドごと、ノートも含む） |
| メール | `.eml` | 件名・差出人・日付・本文（添付ファイル名） |
| Web・データ | `.html` `.htm` `.json` `.xml` `.yaml` `.yml` | HTML は本文だけ、データはそのまま |
| PDF | `.pdf` | ページごとのテキスト（`pip install pypdf` が必要。スキャン画像の PDF は文字を取れません） |

画像や、古い形式（`.doc` `.xls` `.ppt`）は対象外です（Office で新しい形式に保存し直せば読めます）。

**読み込みの流れ**（毎回すべてを読み直さないための仕組み）:

1. **初回の読込** — インデックスが空のときだけ、起動時に範囲内をすべて読み込みます（進み具合はステータスバー、途中で中断可）
2. **変更の確認** — 起動時と範囲を変えたときに、ファイルの日時とサイズだけを見て「未反映 N 件」を数えます（本文は読みません）
3. **更新** — ステータスバーの「更新」、範囲ダイアログの「選択した範囲を更新」、ファイル一覧のフォルダ右クリック →
   「このフォルダを更新」、資料の「再読込」で、**変更・追加・削除されたファイルだけ**を読み込みます。
   Embed モデルを登録していれば、このときに意味検索用の埋め込みも作ります
4. 質問・検索は読み込み済みの索引（転置インデックス・埋め込み）を使うだけなので、資料を読み直しません

Mycel 上でノートを保存・作成・削除したときは、そのノートだけすぐ反映します。

**読み込み範囲**（左の ⛁ ボタン、またはステータスバーの件数をクリック）:
フォルダのチェックを外すと読み込み対象から外れ、「更新」で一覧・検索・AI からも消えます。
「＋ フォルダを追加」で Vault の外のフォルダ（`\\server\share\営業資料` など）を読み取り専用で追加できます。
各フォルダには「読込 12 +3 ~1 −0」（読込済み・新規・変更・削除）とエラー件数が出るので、
変更があるところだけ選んで更新できます。範囲の設定は `<vault>/.mycel/scope.json` に保存されます。

## AI 取り込み（文書をつながったノートにする）

`[[リンク]]` などの記法を持たない文書を、Mycel のノート網に組み込む機能です。左の受信箱ボタン、
`Ctrl+K` →「>AI 取り込み」、またはアプリにファイルをドロップすると開きます。

1. **ファイルを入れる** — ドロップ／クリックで選ぶ／「読み込み済みの資料から選ぶ」（資料画面の「AI でノート化」からも）
2. **AI で下書きを作る** — バックグラウンドで処理します（閉じても続き、ステータスバーに進み具合と中断ボタン）
   - 本文を取り出し、長い文書は区切って 1 区画ずつ LLM に要点を書かせ（map）、まとめて分析します（reduce）
     → タイトル・文書の種類・日付・要約・要点・登場する名前（顧客・人物・製品・案件）・タグ
   - **RAG**: 要約と名前で既存のノート・資料を検索し（BM25 ＋ Embed モデルがあれば意味検索）、
     候補を LLM に見せて本当に関係するものだけを理由付きで選ばせます
3. **確認して保存** — プレビュー／編集で直し、保存先を変えて保存。原本は `資料/` にコピーされ（設定で変更可）、
   ノートのプロパティ `元の資料: [[資料/見積書.docx]]` からたどれます

下書きのノートは、既存ノートの名前に合わせてリンクします（`田中部長` → `[[田中部長（A社）|田中部長]]`）。
ノートの無い名前は `[[ ]]` にせず、人物・組織として登録してつなぎます（設定で `[[ ]]` にすることもできます）。
LLM が未設定・接続できないときも、本文の取り込みとキーワード検索での関連付けだけで下書きを作ります。
下書きは `<vault>/.mycel/ingest/` に保存され、アプリを再起動しても残ります。

**ローカル LLM を基本にしています**（文書を外部に出さないため）。既定の接続先は Ollama（`http://127.0.0.1:11434/v1`）です。
設定の「LLM」で Ollama / LM Studio / llama.cpp server のボタンを押し、「一覧を取得」でモデルを選んでください。

```bash
ollama pull qwen2.5:7b     # チャット（取り込み・質問・要約）。日本語が得意なモデルを選ぶ
ollama pull bge-m3         # 意味検索（Embed モデル。任意）
```

- ローカル LLM は文脈長が短いことが多いので、1 回に送る文字数（既定 3,000 字）と読む区画の上限（既定 24）を設定の「詳細」で調整できます。
  Ollama の既定の文脈長は短めなので、長い区切りにする場合は `OLLAMA_CONTEXT_LENGTH=8192 ollama serve` などで広げてください
- 1 回の応答に時間がかかる場合はタイムアウトを 300 秒以上にしてください
- 取り込み画面の上部に接続先を表示し、ローカル以外の LLM のときは「文書の内容が外部に送られます」と警告します

## 資料の整理とつながり

**フォルダで管理する**（Vault 内の資料。外部フォルダは読み取り専用）

- ファイル一覧の上の「すべて／ノート／資料」で、資料だけの階層表示にできます。フォルダ名の横の数字は中の件数
- フォルダ名をクリックすると**フォルダの一覧**（名前・種類・サイズ・更新日・つながり数）が開きます。▾ は開閉だけ。
  一覧ではチェックで選んで「フォルダへ移動」「AI でノート化」「削除」、2 件選ぶと「つなぐ」
- パソコンのファイルを**ファイル一覧のフォルダ**か**フォルダの一覧**にドロップすると、そのフォルダに資料として追加します
  （AI で要約したノートにしたいときは、それ以外の場所にドロップ → AI 取り込み）
- 資料・フォルダはドラッグでフォルダへ移動できます。右クリック（またはフォルダの ⋯）で名前変更・移動・削除・新しいフォルダ
- 移動・名前変更では、その資料を指している `[[資料/見積.docx]]` や `[[フォルダ/…]]` のリンクも書き換えます。
  本文は読み直さないので、大きな PDF でもすぐ終わります。削除は `.mycel/trash/` へ移動します

**資料同士をつなぐ**

資料（PDF・Word など）には `[[リンク]]` を書けないので、本文の外に「つながり」を持たせます
（`<vault>/.mycel/relations.json`。インデックスを作り直しても消えません）。

- 資料を開いて右の「リンク」タブ →「＋ つなぐ…」で相手のノート・資料を選び、説明（改訂版／添付資料／前提となる仕様など）を付けます
- 「似ているものを探す（AI）」: 資料の内容で RAG 検索し、ローカル LLM が関係のあるものだけを選んで理由を付けます。「つなぐ」で確定
- フォルダの「つながりを提案」: フォルダ内の資料について内容の近い組をまとめて出します（キーワード索引で測るので速い。
  100% ＝ ほぼ同じ内容）。選んでまとめてつなげます
- つながりはグラフに**点線**で表示され、フォルダの一覧に件数が出ます。資料を移動・名前変更しても付いていきます

## 文献管理モード（登録した文献だけで検索・質問・分解）

左の本のアイコンで開きます。ノートや資料とは別に「文献」を登録し、文献だけを対象に探したり聞いたりできます。

**登録** — 「＋ 追加」から

- 読み込み済みの資料（PDF・Word・テキストなど）を選ぶ、またはファイルをアップロード。題名・DOI・年を本文から推定し、
  ローカル LLM があれば著者・掲載誌・要旨・キーワードまで補います（資料画面の「文献に登録」からも）
- BibTeX / RIS を貼り付け（文献管理ソフトや論文サイトからコピー）。DOI・題名が同じものは重複として飛ばします
- 手入力（本文ファイルの無い書籍など。あとから「本文ファイルを結びつける」こともできます）

**検索と質問**

- 検索欄に入れて Enter。登録した文献の本文だけを対象に、Embed モデルがあれば意味検索（キーワード検索と統合）、
  無ければキーワード検索。文献ごとに一致した段落を表示し、状態・タグ・年で絞り込めます。
  上部の「意味検索: 未作成 → 索引を更新」で、文献のファイルだけ埋め込みを作れます
- 「AI」タブは文献だけを根拠に答えます（出典は文献名で、引用文つき）
- 文献の詳細には、内容の近い文献・同じ著者・同じタグの「関連する文献」が出ます

**読む**

- 未読／読書中／読了、★評価、タグ。欄を直すとそのまま保存されます
- 「AI で要約」で目的・手法・結果・限界に分けた構造化要約（長い文献は区切って読みます）。「AI で書誌情報を補完」で空欄を埋めます。
  一覧でチェックすればまとめて実行できます
- 「読書ノートを作る」で `文献/<題名>.md` を作ります（書誌情報・要約・メモ欄・原本へのリンク入り）
- 引用: APA / IEEE / BibTeX をコピー。エクスポートは BibTeX / RIS / CSV / 引用一覧

**文献同士をつなぐ**

- 文献の詳細の「文献同士のつながり」→「＋ つなぐ…」で相手を選び、関係の種類を付けます:
  引用している / 発展させている / 支持している / 反論している（向きあり）、比較対象 / 同じテーマ / 関連（向きなし）。説明も書けます
- 「つながりを提案（AI）」: 内容の近い文献を集め、ローカル LLM が種類と理由を判断します（LLM 未設定なら内容の近さだけで候補を出します）。種類を直してから「つなぐ」
- 「引用関係を検出」: 本文（参考文献欄など）に他の登録文献の DOI・題名が出ていれば「引用している」と自動で結びます。⋯ メニューから全文献に対しても実行できます
- つながりはグラフに実線（向きがあれば矢印、近づくと種類の文字）で出ます。付けたつながりがある組には、内容の近さの点線は出しません。× で外せます

**分解グラフ**（グラフタブ）

```
分類（タグ・著者・年・種類・読了状態）  ─ クリック ─▶  文献  ─▶  章・ページ  ─▶  段落
```

- 大きい要素をクリックすると小さい要素が開き（＋／−）、もう一度クリックで閉じます。Shift+クリックで文献・ファイルを開きます
- どの階層でも、内容の近い要素を点線で結びます。開いている最も細かい要素に結ぶので、
  ある文献の「4. 結果」が別の文献そのもの・章・段落のどれとつながるかが見えます
- 文献の詳細の「章立て」をクリックすると、その章まで開いた状態でグラフに移ります

文献の登録情報は `<vault>/.mycel/library.json` に保存されます（本文は読み込み範囲の資料のまま）。

## 人物・組織（誰が何に出ているか）

左の人のアイコンで**人物・組織の一覧**が開きます。名前をクリックすると、その人のページになります。

- **登場する文書**: どの文書に、どんな立場（決裁者・窓口・出席者・差出人・宛先など）で出ているか。新しい順
- **所属**: 文書に「田中部長（A社）」「B社 佐藤課長」のように書かれていればそれを、無ければ一緒に出てくる組織から推定（「?」付き）
- **一緒に出てくる人・組織**: 同じ文書に出てくる回数の多い順
- **関係がありそうな文書**: 名前は出てこないが、所属・一緒に出てくる人・案件の言葉で検索して推定したもの
- **AI で人物像を推定**: 登場する文書の該当箇所を集めてローカル LLM に渡し、「所属と立場／関わっている案件／他の関係者との関係／次に会うときのヒント」を根拠 [番号] 付きでまとめます

文書側では、右の「リンク」タブの**登場する人物・組織**に出ます。グラフで「人物」をオンにすると、◆（人物）▲（組織）を介して、
リンクの無い文書同士もつながって見えます。

**見つけ方**

- 自動（ルール）: 「田中部長」「鈴木様」「スミス様」「株式会社○○」「○○（株）」「A社」、メールの差出人・宛先・CC、
  「出席者：」の行、`[[田中部長（A社）]]` のようなリンク、プロパティの `顧客: A社`。「更新」のたびに変わった文書だけ処理します
- AI（手動）: 人物パネルの「AI で詳しく抽出」で、まだ AI で読んでいない文書だけをローカル LLM が読み、フルネーム・所属・立場を補います
- AI 取り込みで LLM が見つけた名前も、保存したノートと原本に登録します（`[[ ]]` のリンクは既定で作りません）
- 「田中部長」と「田中 太郎」は、同じ組織ならまとめます（姓だけの呼び方 → フルネーム）

**直し方（つないだら外せる）**

| したいこと | 操作 | 戻し方 |
|------------|------|--------|
| この文書から外す | 人物ページの文書の行の ×、または文書の「登場する人物・組織」の × | 文書の「外した人を戻す」 |
| 抽出されなかった人を足す | 文書の「＋ 人物・組織を追加」（`田中部長（A社）` と書くと所属も記録） | 足した人の × |
| 同じ人をまとめる | 人物ページの ⋯ →「同一人物としてまとめる」 | 「別の呼び方」の × |
| 人名ではないものを消す | 人物ページの ⋯ →「人名ではない」 | 人物パネルの「除外した名前」→「戻す」 |

外した・足した・まとめた指定は `<vault>/.mycel/entities.sqlite` に保存され、文書を読み直しても残ります。
同じ名字の別人（別の会社の田中さん）は自動では分けられません。所属が複数ある人には「所属が複数」と表示するので、
違う文書から外してください。

## GraphRAG（選んだときだけ使う）

標準の質問は「関連する段落を検索して LLM に渡す」方式で、速く、索引は「更新」のものをそのまま使います。
GraphRAG は文書全体にまたがる「誰と誰がどうつながっているか」「全体としてどんな傾向か」に強い代わりに、
索引作りに LLM の呼び出しが文書数分かかります。そのため**既定は標準のまま**で、使うときだけ選びます。

1. AI タブの「方式」で **GraphRAG（自動／局所／全体）** を選ぶ（選択は設定 `rag_mode` に保存）
2. 「GraphRAG の索引を作る」を押す。対象は「対象」の範囲（全体／Vault／外部フォルダ／フォルダ）。
   バックグラウンドで進み、途中で止められる。2 回目以降は**変わった文書だけ**抽出し直し、
   メンバーが変わらないコミュニティの要約は使い回す
3. 質問する。回答の下に、たどった実体・関係・コミュニティが折りたたみで出る

| 方式 | 使いどころ | 仕組み |
|------|-----------|--------|
| 標準（既定） | 「A社の決裁者は？」など、該当箇所を探す質問 | 段落の検索（BM25 ＋ 意味検索）→ LLM |
| GraphRAG 局所 | 「田中部長は何に関わっているか」など、実体をたどる質問 | 質問中の実体と検索でヒットした段落の実体を起点に 1 ホップ広げ、関係・所属コミュニティの要約・段落を LLM に渡す |
| GraphRAG 全体 | 「全体の傾向をまとめて」など、俯瞰する質問 | コミュニティ要約ごとに部分回答（map）→ 統合（reduce） |
| GraphRAG 自動 | 迷ったら | 質問にグラフ上の実体があれば局所、「全体」「傾向」「まとめ」などがあれば全体 |

- **知識グラフの表示**: グラフタブの「知識グラフ」をオンにすると、文書のグラフに実体（人物 ◆・組織 ▲・製品や概念などは六角形）と
  実体同士の関係（説明つきの線）を重ねます。1〜2 ホップではその文書の実体と 1 ホップ先、全体では言及文書の多い実体から 60 個。
  同じ実体に出てくる文書は実体を介してつながって見えます
- **文書同士をつなぐ**: 実体をクリックすると説明・関係・登場する文書が出ます。文書にチェックを付けて「チェックした文書をつなぐ」を押すと、
  その組を「つながり」（説明「共通: 実体名」）として保存し、資料の「つながり」欄やグラフの点線に出ます（既にある組は飛ばします）。
  [[リンク]] を書く、資料の「つながり」で手動／AI 提案から結ぶ、人物・組織で自動的につながる、の各方法と併用できます
- LLM が未設定のときは、人物・組織の規則抽出と同じ文書内の共起で簡易な知識グラフを作ります（要約は箇条書き）
- 索引は `<vault>/.mycel/graphrag.sqlite`。壊れても「GraphRAG の索引を作る」で作り直せます
- 設定 `graphrag_max_chunks`（1 文書あたり抽出する段落数、既定 40）、`graphrag_max_communities`（全体質問で読む要約の数、既定 12）で時間と精度を調整できます

## LLM の設定

左下の ⚙ → 「LLM」で登録し、「保存して接続テスト」で確認します。設定は `mycel/mycel.config.json`
に保存されます（API キーを含むため .gitignore 済み。画面にはキーを返しません）。

| 接続先 | 接続方式 | Base URL の例 | モデル |
|--------|----------|---------------|--------|
| Ollama（既定） | OpenAI 互換 | `http://127.0.0.1:11434/v1` | `qwen2.5:7b` など（「一覧を取得」で選べる） |
| LM Studio | OpenAI 互換 | `http://127.0.0.1:1234/v1` | 読み込んだモデル名 |
| vLLM / llama.cpp server | OpenAI 互換 | `http://127.0.0.1:8000/v1` | 起動時のモデル名 |
| OpenAI | OpenAI 互換 | `https://api.openai.com/v1` | `gpt-4o-mini` など（API キー必須） |
| Azure OpenAI | Azure OpenAI | `https://<リソース名>.openai.azure.com` | **デプロイ名**（API バージョンも指定） |

- **Embed モデル**（任意）を登録して「更新」を押すと、まだ埋め込みの無い部分だけ埋め込みを作り、
  キーワード検索に意味検索を併用します（RRF で統合）。未登録でも文字バイグラムの BM25 で関連ノート・資料を探します
- LLM が未設定でも「ノートに質問」は関連ノートの一覧を返します
- 社内プロキシが必要な場合は「プロキシを使う」をオン（URL 空欄なら環境変数 `HTTPS_PROXY`）
- 推論モデルの `<think>…</think>` は回答から除きます
- テンプレートフォルダのノートは AI の根拠から除外します

## 共有に向けた仕組み（プラグイン）

当面は個人利用が前提ですが、将来チームで共有できるよう次を先に入れてあります。

- **楽観ロック**: 保存時に読み込んだ版（内容ハッシュ）を送り、先に誰かが書き換えていれば 409 で競合を返す
- **作成者名**: 設定の「作成者名」をすべての変更イベントに付ける
- **変更ジャーナル**（既定で有効）: `.mycel/plugins/change_journal/journal.jsonl` に変更を追記
- **プラグインの差し込み口**: 保存前（止める・ロック）／保存後・作成・削除・名前変更（同期・通知）／Vault を開いたとき（取り込み）／独自 API
- 同梱プラグイン: `change_journal`（変更ジャーナル）、`git_history`（Git 自動 commit と履歴 API）、`shared_vault`（共有のひな形・未実装）

作り方と共有に進むときの手順は [PLUGINS.md](PLUGINS.md) を参照してください。

## 構成

```
mycel/
├─ server.py            HTTP サーバ・API ルーティング・CSRF / DNS リバインディング対策
├─ mycelcore/
│  ├─ app.py            アプリ本体（保存・作成・名前変更・削除・デイリーノート・テンプレート・読み込み操作）
│  ├─ extract.py        資料の読み込み（docx / xlsx / pptx / eml / html / csv / pdf など）
│  ├─ ingest.py         AI 取り込み（文書 → 要約・名前・タグ・RAG で関連付けたノートの下書き）
│  ├─ entities.py       人物・組織の抽出（ルール・LLM）と名寄せ・保存（.mycel/entities.sqlite）
│  ├─ library.py        文献管理（登録・BibTeX/RIS・文献限定の検索と質問・構造化要約・分解グラフ）
│  ├─ people.py         人物ページ・登場する文書・関係者・AI による人物像の推定・グラフ
│  ├─ relations.py      資料同士のつながり（.mycel/relations.json）
│  ├─ scope.py          読み込み範囲（除外フォルダ・外部フォルダ・形式・サイズ上限）と走査
│  ├─ jobs.py           バックグラウンド処理（読み込み・確認）の進み具合と中断
│  ├─ vault.py          ファイルの読み書き（パス検証・原子的な保存・版・ゴミ箱）
│  ├─ links.py          [[リンク]]・#タグ・見出し・プロパティの解析、リンクの書き換え
│  ├─ index.py          SQLite インデックス（差分読み込み・FTS5・リンク表・タグ表・AI 用チャンクと転置インデックス・埋め込み）
│  ├─ ai.py             ノートに質問・要約・リンク候補・書き換え、検索（BM25 ＋ 埋め込み）
│  ├─ graphrag.py       GraphRAG（実体・関係の抽出、コミュニティ検出と要約、局所／全体の質問。.mycel/graphrag.sqlite）
│  ├─ llm.py            OpenAI 互換 / Azure OpenAI クライアント
│  ├─ plugins.py        プラグインの仕組み
│  └─ config.py         設定の保存（キーは画面に返さない）
├─ plugins/             change_journal / git_history / shared_vault
├─ static/              画面（index.html・app.js・markdown.js・graph.js・style.css）
├─ sample_vault/        初回に入れるサンプルノート
└─ tests/               ユニット・API テスト（モック LLM で実 LLM 不要）
```

インデックスは `<vault>/.mycel/index.sqlite` に置くキャッシュで、壊れても元のファイルから作り直せます
（`Ctrl+K` → `>インデックスを作り直す`。すべて読み直すので資料が多いと時間がかかります）。
