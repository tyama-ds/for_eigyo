# Local Chat

OpenAI互換APIを持つローカルLLMと会話する、Windows向けの小さなチャットアプリです。Pythonで動くローカルサーバーとブラウザー画面を使います。LLMサーバーは別途用意してください。

## 起動

初回は、このフォルダー内の **`Setup.cmd`** で依存パッケージを準備してください。その後 **`Launch.cmd` をダブルクリック**すると、画面が開きます。セットアップ済みの環境では `Launch.cmd` だけで起動できます。

1. 「接続・設定」で API URL を指定します。LM Studioの例は `http://127.0.0.1:1234/v1`。別PCのサーバーも、そのLANアドレスやホスト名で指定できます。
2. 必要な場合はAPIキーを入力し、設定を保存します。「モデル一覧を取得」でモデルを確認するか、モデル名を直接入力します。
3. メッセージを送ります。ファイルは添付ボタン、ドラッグ＆ドロップで追加できます。

既定の画面: [http://127.0.0.1:8840](http://127.0.0.1:8840)。停止は起動コンソールで `Ctrl+C`。別ポートは `Launch.cmd --port 8841` で指定できます。

## 別のPCで使う

Python 3.11以降（このPCでの検証は3.13）とEdge/Chromeなどのブラウザーが必要です。Python本体は同梱しません。

1. このフォルダーを配置します。`.venv` と `data` はコピー不要です。
2. `Setup.cmd` を実行します。初回はPythonパッケージを取得します。
3. `Launch.cmd` を実行します。

Pythonの場所を指定したい場合や、初回インストールにもプロキシが必要な場合は、コマンドプロンプトで実行します。

```bat
set "LOCAL_CHAT_PYTHON=C:\Python313\python.exe"
Setup.cmd --proxy "http://proxy.example:8080" --certificate "C:\Certificates\company-ca.pem"
```

オフラインでの初回セットアップには、同じOS・Python版向けに事前取得したwheelを指定します。

```bat
Setup.cmd --wheelhouse "C:\Packages\local-chat"
```

オンラインの準備用PCでは `python -m pip download --only-binary=:all: -r requirements-lock.txt -d wheelhouse` で依存wheelをまとめられます。通常起動時にパッケージのダウンロードはしません。

## 接続の流れとプロキシ

```text
ブラウザー → このPCのLocal Chat → Local LLMのAPI（直接接続）
                            └→ 外部Web（直接 / 環境変数 / 指定proxy）
```

LLMサーバーがインターネットへ接続する必要はありません。Webの取得は、アプリを起動しているPCが行い、取得した本文をLLMへ渡します。

「接続・設定」の外部通信には次の選択肢があります。

- **直接接続**: プロキシ環境変数を使いません。初期設定です。
- **環境変数**: 起動時の `HTTP_PROXY` / `HTTPS_PROXY` / `ALL_PROXY` / `NO_PROXY` を使用します。環境変数がない場合は、HTTPXがWindowsの静的システムプロキシ設定を参照する場合があります。PAC・自動構成スクリプトには対応しません。HTTP(S)方式のプロキシを指定してください。
- **手動指定**: `http://proxy.example:8080` などを入力します。認証が必要ならURLにユーザー名を入れ、パスワードは専用欄に入力します。ユーザー名の特殊文字はURLエンコードしてください。

LLMの接続は、外部通信のプロキシ設定・環境変数にかかわらず直接接続します。社内CAは「追加CA証明書」に、このPCのPEMファイルの絶対パスを指定します。これはLLM・WebのTLS検証に使用されます。TLS検証を無効化する設定はありません。

HTTPXの仕様: [プロキシ](https://www.python-httpx.org/advanced/proxies/)・[環境変数](https://www.python-httpx.org/environment_variables/)。インストール時のpip設定と、アプリ実行中の通信設定は別です。

## Webを参照する

- **URLを添付**: ツール呼び出し非対応のモデルでも使えます。入力したURLをPCが取得し、本文を添付資料にします。
- **Web参照を有効化**: LLMが `web_fetch` ツールでURL取得を要求できます。OpenAI互換の `tool_calls` 対応が必要です。通常の会話では無効にできます。

対象は公開HTTP(S) URLのHTML・テキストです。検索エンジンによるキーワード検索、ログイン済みブラウザーの共有、JavaScript実行、社内サイトの取得には対応していません。リダイレクト先も検査します。取得先名をこのPCでDNS解決できる必要があります。プロキシ側の名前解決やDNS変更まで完全に隔離する仕組みではありません。

Web本文は1ページ4 MB・40,000文字までです。自動取得は1回答で4ページまで、LLMに渡す本文は参照文字数の残りに合わせて省略します。添付資料・ユーザーの質問そのものを検索サービスへ送る処理はありません。ただしWebを有効にした会話では、モデルが生成した取得URLが外部へ送られます。

## 添付ファイル

| 種類 | 読み取り方法 |
| --- | --- |
| TXT / Markdown / CSV / TSV / JSON / ソースコードなど | テキスト。UTF-8・BOM付きUTF-16・CP932 |
| HTML / JavaScript | HTMLは本文抽出（script・styleを除外）、JavaScriptはソースコードとして読み取り。実行・プレビューは行いません |
| PDF | ページ単位の文字抽出。OCRは行いません |
| DOCX | 本文・表・ヘッダー・フッターの文字 |
| XLSX | シートごとのセル。数式は式として読み、再計算しません |
| PPTX | スライド・表・ノートの文字 |
| PNG / JPEG / WebP / GIF | 設定の「画像を送信」を有効にし、画像対応モデルへ送信 |

1ファイル20 MB、1メッセージ10ファイルまで。文字抽出は各80,000文字までで、送信時にも参照文字数へ収めます。省略は画面に表示します。Excelは20シート・各1,000行×50列、PDFは500ページまで。画像は長辺2,048pxへ縮小し、アニメーションは先頭フレームを使用します。Office内の画像・グラフを視覚的に解釈する機能はありません。

旧形式の `.doc` / `.xls` / `.ppt`、ZIP、音声・動画、パスワード付き文書は対象外です。対応形式へ変換して添付してください。ファイルに含まれるプログラムやマクロは実行しません。

## 保存と会話

会話、抽出済みの添付テキスト、変換済み画像、接続設定を、このフォルダーの `data/chat.sqlite3` に保存します。添付元ファイルの原本は保存しません。データベースは暗号化していません。会話を削除すると、その会話に送信済みの添付データも削除されます。未送信の添付は7日経過後の起動時に整理されます。

APIキーと手動プロキシのパスワードはメモリー内だけに保持し、再起動時には再入力が必要です。起動前の環境変数 `LOCAL_CHAT_API_KEY` / `LOCAL_CHAT_PROXY_PASSWORD` でも渡せます。保存先は `LOCAL_CHAT_DATA_DIR` で変更できます。

古い会話は参照文字数を超えると今回の送信から省略し、通知します。保存履歴は残ります。文字数はトークン数の概算管理なので、モデルのコンテキストが小さい場合は参照文字数・出力トークンを下げてください。大量資料の索引作成やRAGは行いません。自動Web取得の全文は取得したターンだけで使用し、履歴には回答と参照URLを保存します。

回答は逐次表示し、停止・コピー・Markdown保存ができます。停止・通信失敗時も受信済みの回答を保存します。非常に長い回答は画面の表示を先頭80,000文字までに制限し、コピー・Markdown保存では全文を取得できます。

### 思考と回答の分離

Qwenなどが返す `<think>…</think>` と、APIの `reasoning_content`（または文字列の `reasoning`）を回答本文から分けて表示します。「思考過程」は初期状態で折りたたまれ、クリックで開閉できます。生成中は「思考中…」と表示します。タグが通信の途中で分割されても処理し、Markdownのコード内に書かれたタグはコードとして保持します。

回答のコピーボタンでは本文だけをコピーし、思考欄には専用のコピーを用意しています。Markdown保存では思考と回答を見出しで分けます。停止・通信失敗時も受信済みの思考を残し、過去の会話を開くと同じ区分で表示します。旧形式の履歴に保存された思考タグも起動時に分離します。次の質問やWeb取得後の再問い合わせに送る履歴には、回答本文だけを使います。

思考だけで出力が終了した場合は、回答本文がないことを表示します。必要に応じて最大出力トークン数を増やしてください。区切りも専用フィールドもない文章は、思考と推測せず本文として扱います。両形式を重複して返すサーバーでは、各生成ラウンドで最初に届いた思考形式を使い、同一フレームなら専用フィールドを優先します。思考フィールドの再送を必須にするサーバー独自のtool calling仕様には対応していません。

## 開発・検証

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m chat_app --no-browser
```

バックエンドはFastAPI / httpx / SQLite、画面は外部配信ライブラリーに依存しないHTML/CSS/JavaScriptです。`127.0.0.1` のみで待ち受け、別サイトからの操作を制限します。複数ユーザー向け公開サーバーではありません。

テストでは模擬OpenAI互換サーバーを使い、ファイル読み取り・プロキシ分離・ストリーミング・保存・切断を確認します。実際のLLM、組織のプロキシ、組織のCAとの接続は、実際の設定値で確認してください。
