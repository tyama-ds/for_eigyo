「探索ラボ」は、検索結果を追加するたびに分類候補・優先順位・次の検索案を更新するための作業タブです。全固体電池なら、電池構造だけでなく、材料、製造、界面、性能、用途の6観点から調べます。まずCSVで検証し、必要になった段階で外部検索を接続できます。

ここでいう「自己改善」は、公報の分類メタデータ、人の必要・不要判断、実行履歴を蓄積して探索を更新することです。探索ラボを使うだけでTransformerやLLMの重みが再学習されるわけではありません。既存の手動探索にある学習機能は、従来の操作で実行します。

1. 「探索ラボ」で主題を入力し、「探索計画を作る」を押します。6観点と公式分類辞書からの仮説が出ます。LLMによる語句補完は任意です。
2. 手動探索に読み込んだCSVを使う場合は「取込済みCSVで検証」を押します。別の検索結果は「次のCSVを追加して分析」でラボへ追加します。
3. 候補ごとに根拠公報、支持の集計、必要・不要判断を確認します。関連する分類を選び、手動探索へ送ります。これは候補への追加であり、検索式に使う分類はコンステレーションで選択します。
4. 手動探索のStep 1で利用するデータベースの形式を選び、次の検索を実施します。その結果CSVをラボへ追加すると、累積公報に基づいて候補と検索案が更新されます。
5. 計画・公報・根拠・ラウンド履歴はJSONで書き出せます。新しい計画を作ると前の計画は自動でアーカイブされ、履歴から書き出せます。

「LLMで観点・英語を補完」は、英語の主題語 `english_terms` と6観点ごとの日本語等の語句 `terms`・英語語句 `english_terms` をJSONで受け取ります。英語主題語は主題検索と各観点の検索案へ、観点の英語語句は対応する検索案へ、観点の日本語等の語句はCSV内の名称・要約から観点を判定する処理へ反映します。この操作で手動探索の分類選択や検索式は自動変更されません。通常のラボ用LLM依頼は分類コードの直接生成を求めておらず、ラボの分類候補は補完後の語句を用いた公式辞書との照合などから作ります。

計画にはLLMを使った日時、実際に追加された語句・観点・分類仮説、反映された検索案のID、追加しなかった理由を `llm_proposal` として保存します。重複だけの返答でもLLM使用済み・新規追加0件と記録します。不正なJSON構造（空のオブジェクト、別のキー、配列でない語句など）はエラーにし、既存の計画を保持します。生のLLM応答や接続情報はこの記録に保存しません。従来の計画には反映記録がないため、語句がLLM由来だったかを後から断定できません。

手入力の英語とLLMの英語は合成して保持します。英語の主題語は入力主題の英語・既定対訳、手入力、LLM追加の順で最大8語とし、各検索案はその先頭6語を使います。検索案に入らなかった主題語は反映記録の注意に表示します。観点ごとは日本語等12語・英語4語までで、重複・形式不適合・上限超過を除きます。追加内容と検索案を確認してから、CSV検証や外部検索へ進んでください。

ラボへ追加したCSVは、手動探索の特許群を置き換えません。ファイルは20 MB以下、累積は重複をまとめて5,000公報までです。公報番号が同じ文献は統合します。名称列を認識できない場合は、手動探索の列割り当てで読み込んでから検証してください。手動探索で変更した必要・不要判断は「取込済みCSVで検証」で反映されます。CSVモードは追加されたデータの分析であり、外部検索を自動実行した結果ではありません。

「分類候補を見比べる」は、技術内容の近い候補をまとめたマップと、選んだ候補の詳細を並べて表示します。マウスを重ねるかキーボードでフォーカスすると、日本語・英語の名称、根拠公報、支持の内訳を確認できます。出典（公報由来・探索仮説・合成デモ）、技術の観点、コード・両言語の名称、選択済みで絞り込めます。地図内をスクロールし、表示倍率で大きさを調整できます。狭い画面では詳細を地図の下へ表示します。

候補はクリックまたは囲み操作でまとめて選択できます。絞り込みで見えなくなった選択も保持します。「リスト」へ切り替えて全文を順に確認することもできます。マップの距離は技術内容の近さの目安で、特許の適合性・件数の大小を表すものではありません。色は根拠の種類、円内の数字は支持集計です。ラボの選択は手動探索の検索用選択と独立しています。「手動探索へ送る」で候補へ追加してから、検索に使う分類を決めます。

ラボにも名称の日本語 / English切り替えがあります。対話タブとは独立した表示設定です。分類の日本語収録範囲と参考訳の扱いは[分類ガイド](CLASSIFICATION_GUIDE.md)を参照してください。

候補には、次の種類の根拠があります。

| 表示される候補 | 根拠と読み方 |
| --- | --- |
| 辞書からの仮説 | 公式IPCの名称と観点語などの一致。コードが存在することと、主題に適合することは別です。隣接技術や対象外の分類も含みます。 |
| 公報からの候補 | 取り込んだ公報の分類欄に、実際に記載されていたコード。名称や要約だけから分類の付与を推測しません。必要判定がない候補は適合性の確認待ちです。 |
| FI・テーマ対応からの候補 | FIのIPC部分、またはF-termの公式テーマFI範囲から得た上位IPCの探索候補。公報に付与されたIPCではありません。由来・版・原文を表示し、IPC欄からの件数と分けて集計します。 |
| 辞書未確認の分類欄 | 取り込み原文は保持しますが、収録辞書でコードの存在を確認できない分類。未確認IPCを実付与IPCの確認済み根拠には使いません。 |

同じ主題で既存候補を引き継ぐ場合も、以前の候補であること自体は公報による裏付けになりません。新しい主題が手動探索の主題と異なる場合、旧候補は新計画の仮説へ自動で取り込みません。手動探索側の候補は保持されます。

支持の優先順位は、同じファミリーの公報を重ねて過大評価しないよう集計します。ファミリーIDがない公報は、公報番号単位で代用し、その件数を表示します。したがって、この代用分まで「異なる発明の数」と解釈できません。必要側の基礎点は1集計単位につき1、利用者の「必要」は1.5、AIの「必要」は0.75を別に加点します。同じ集計単位に人とAIの必要判定がある場合は人だけを加点します。人の「不要」は0.5、AIの「不要」は0.25を差し引き、重なる集計単位は人を優先します。「不要」の公報は正の支持と語句抽出から除いて別集計し、自動でNOT条件を作成しません。元の人・AI判定は書き換えません。

IPC欄由来とFI・F-term対応由来の件数は、同じ公報が両方を持つと重複します。支持の合計では公報・ファミリーを重ねて数えません。FI・テーマ対応だけで得た候補も次の探索に利用できますが、公報付与IPCという説明にはしません。分類対応には対話で探索・次の式への反映と同じ `classification_bridge.extract` を使います。[分類ガイド](CLASSIFICATION_GUIDE.md)に対応範囲と版の説明があります。

合成デモには明示的な印が付きます。実在特許の調査実績ではなく、外部IPC探索の根拠には使いません。IPCは収録済みの公式辞書で照合します。個別F-termの辞書収録は5H029で、F-termテーマとFI範囲の対応表は2026年6月版3,390件です。CPCの公式階層辞書は未収録です。未確認の分類を、確認済みIPCと同一視しません。件数・順位・探索の収束は、関連性や検索再現率、網羅性の保証ではありません。

処理は `discovery_engine.py` の計画・根拠集計、`discovery_routes.py` の蓄積・履歴・手動探索との接続、`patent_search.py` の外部取得に分かれています。生成候補は最大60件、次回の検索案は最大12件です。再帰検索には元の主題語を残し、分類で絞った検索と、分類を限定しない観点検索を組み合わせます。

EPO OPS接続は任意の拡張として実装されていますが、この環境で認証情報を使った実サービスへの接続試験は未実施です。利用にはOPSの登録とOAuth認証情報が必要です。OPSはEPOのデータをREST/XMLで取得するサービスです。[EPO OPS公式案内](https://www.epo.org/en/searching-for-patents/data/web-services/ops)

接続する場合は「表示・接続設定」にOPSのキー・シークレットと必要なproxyを入力します。認証情報とproxyはメモリー内で扱い、設定ファイルへ保存しません。ラボの自動検索は1実行あたり最大3ラウンド・12検索・1検索25公報に制限し、利用者の停止、未実行候補の消尽、追加情報の停止などで終了します。OPSへの検索語・IPCの送信は「EPO OPSで再帰検索」を実行したときです。

ラボ内のコピー用検索式はEPO OPS向けCQLです。J-PlatPat、Derwent、Espacenetなどへ貼る式は、引き続き手動探索のStep 1で対応形式を選んでください。EPOは自動取得にOPSなどのRESTインターフェースを案内しており、Espacenetの画面を巡回するロボットとは区別しています。[EPO Fair use charter](https://www.epo.org/en/service-support/ordering/fair-use)

現在の再帰は「主題語・観点 → 公報 → 公報のIPC・発見語 → 次の検索」です。引用・被引用特許のリンクをたどる引用ネットワーク探索は未実装です。将来は引用関係、ファミリー単位の代表公報選択、利用者が指定した既知関連特許の回収確認を追加することで、次に調べる範囲と取りこぼしの確認を改善できます。
