# 調査ワークフローの統合監査

対象: 調査ナビ、観点からの検索式、保存ターゲット、過去式の調整、投影・評価、LLM判定の接続。初回統合のプロンプト版は `patent-research-2026-09-18-v1`。和集合・積集合の更新版 `patent-research-2026-09-18-v2` の追加監査は末尾に分けて記録します。この記録は実装とテストで確認した範囲を示し、検索網羅性やLLMの実務精度を保証するものではありません。

## 監査で見つけて修正した食い違い

- 探索ラボと分類提案のJSON契約が異なるため、ラボを専用の `english_terms / facets` プロンプトへ分離した。
- 入力画面・API・計画エンジンは目的300文字、説明5000文字、観点8件・160文字、ターゲット20件に揃えた。過去式の調整目的も300文字以内とする。
- 8観点に割り当てられなかったKWは保持・表示し、省略の明示確認なしには式へ適用しない。分類辞書に渡す語の数は別途制限し、辞書仮説用に使わなかった語も観点から消さない。
- 入力を変更した後の古い観点案・プレビューの適用や、生成中に編集した入力の消失を防いだ。
- CSVを置き換えるたびにターゲット本文が消える問題を、別の参照保存で解消した。手動で特許を追加するときも、その時点で選択されている既存ターゲットをすべて保存する。
- 新しいCSVで同IDの要約や分類が空の場合は、計画用の参照だけを保存済みターゲットから補完し、補完した項目を注記する。検索結果CSVの空欄自体は書き換えない。
- 公報番号のハイフン・空白・大小文字の違いでターゲット回収が0件になる問題を、既存の公報番号キーに揃えて修正した。同一公報の別表記を二重計上しない。
- 観点から作った式を既存の改善操作へ渡した際、OR群・NOTの範囲を平坦なKWへ戻さず保持する。改善語を追加してから取り消しても元の論理木へ戻ることを確認した。
- 自動補完したLLM判定基準を入力欄へ戻すと、次回は古い文字列が明示基準として扱われるため、入力欄は空のまま、実際に使った基準を別表示にした。
- 検索式とCSVの対応が未確認の場合、採用記録にその旨を明示する。対応していない結果のS/Nを、当該検索式の実行検証として保存しない。
- Local LLMの生成時間超過が接続失敗と同じ表示になる問題を分離した。接続設定に応答待ち時間30〜600秒（既定120秒）を追加し、生成を短くするプロンプトを補足した。実際の保存設定を自動で延長せず、入力条件の保持も継続する。
- LLMが具体語と抽象語に同一の語を重複して返す場合は、妥当な計画まで拒否せず、具体語を優先して重複を整理する。配列の生の件数上限と全語の構文を先に確認し、大小文字だけ異なる同一語以外の統合は行わない。
- LLMが入力観点のIDを返さない場合は、利用者の原文アンカーを先頭に復元する。別IDの提案と意味から対応付けず、理由欄に入力の保持・抽象化未実施を表示する。8観点を超える追加提案は省略数を表示する。省略する提案も含めて先に全件を検証し、同IDの名前・役割の変更・保持必須KWの欠落や、不明な根拠IDは引き続き拒否する。

## 現時点の限界

- 新しいWeb検索API、J-PlatPat自動操作、全DBを巡回する自動取得は追加していない。ターゲット探索は既存の検索サービス・CSV・手動入力、探索ラボの設定済みOPSを利用する。
- J-PlatPatの対応するBoolean構文とPatent Atlas JSONは論理木として編集可能。その他のDBの任意のコピペ式や未対応構文は原文の参照保存になる。既存のDB別「出力」対応と、任意形式の「取り込み」対応は同じ範囲ではない。
- 過去式の自動提案は語句・分類の置換を対象とする。論理構造まで変える必要がある場合は確認事項に示し、既存の構造を勝手に変更しない。
- 観点起案で送信するターゲットは最大20件、名称250文字・要約1500文字まで。請求項全文は取り込まない。抽象化の提案は原文の記載や法的な権利範囲の証明ではない。
- UMAP用の `umap-learn` は通常の `requirements.txt` に追加済み。既存環境では更新後に `python -m pip install -r requirements.txt` を実行する。UMAPだけを追加する `requirements-map.txt` も利用できる。未導入の場合はエラー理由と以前の配置を保持し、別の手法をUMAPとして表示しない。t-SNE/UMAPは4件以上が必要。
- 地図は名称・要約のTF-IDF表現を投影する。2D上の近さ・移動線はナビゲーションであり、関連性の正解や方式間で比較できる距離ではない。
- 人が確認したS/N、既知ターゲットの回収、境界候補、収束表示を合わせて実務者が判断する。未知の関連特許を含めた網羅率、LLMの校正済み確率、特許性・侵害の結論は算出しない。
- 公報番号の同一性は既存の表記正規化に揃える。出願番号と公開番号の相互変換、国ごとの番号体系の完全な照合、同族特許の同一視を追加したものではない。

確認した範囲では、対象条件・根拠の由来・論理構造・判定の帰属を手順間で保持できる。実テーマでの式の精度は、使用DB・検索日時・件数・既知ターゲットの回収と、人が確認した必要・不要・保留を記録して評価する。

## v2: 和集合・積集合の追加監査

この節は入力KWを一律ANDにして狭めすぎる問題への追加修正を記録する。上の初回統合時点の件数は履歴として保持し、今回の件数へ上書きしない。

| 観点 | v2の規則と確認範囲 |
|---|---|
| 意味関係でOR/ANDを使い分ける | 一般語・専門語という区分だけでは決めない。同一探索軸の同義語・代替表現をOR、独立した必要条件をANDにする。新たなLLM観点は通常optionalを推奨し、利用者が指定していない必須条件を安易に増やさない。 |
| 説明可能なオフライン仮OR | 自動運転関連、電池の英日表記、固体電解質の英日表記の3軸だけを使う。未知語を意味推定で統合せず、全分野を網羅する辞書だとは表示しない。LLMには未知分野のグループと理由を提案させる。 |
| 観点ID・元KWを保持 | 観点を削除・再命名せず、同じ非空 `or_group` を付けて和集合にする。語句とグループは画面で確認・編集できる。検索語の生配列・一意語数上限や根拠ID検証は緩和しない。 |
| 明示必須・除外を保護 | `必須:` / `required:` はPython算出の `locked_and=true` とし、他観点のORにしない。LLMはこの属性を返して変更できない。除外観点も肯定OR群へ入れない。接頭辞なしの観点は既定独立だが手動グループ編集が可能。 |
| 古いLLM応答との互換性 | `or_group` キー欠落は入力アンカーの既定を継承し、明示空文字は独立ANDとする。欠落した入力アンカーの原文復元にも既定グループを残す。旧応答に新フィールドを必須にしない。 |
| 手順間の意味を保持 | 新規初案・観点式・改善・要否判定でOR群の意味を保持する。判定へグループと検索条件の論理木を渡し、同群の全項目を同時に必須とはしない。保存済みの古い式は自動で書き換えない。 |

例の `自動車 AND (自動運転 OR 運転システム)` は、A=自動車、B=自動運転、C=運転システムとすると `A ∧ (B ∨ C)` である。AとBだけ、またはAとCだけがある場合も真になる。Aだけ、またはAを欠く場合は偽になる。`A ∧ B ∧ C` への置き換えとは結果集合が異なることを確認する。運転システムは厳密な同義語ではなく広い代替表現なので、実検索で不要例と既知の必要例の回収を確認する必要がある。
