# Research Atlas：論文内容に基づく予測・評論・推薦システム設計

設計提案 v1.0 / 2026-09-14。アプリへの追加実装前。

## 01 / PURPOSE | 論文から、次の研究候補を見つける

研究の伸びと実用化の見通しを、別々の根拠で評価する

設計提案 v1.0  |  2026年9月14日
本書は既存アプリへの追加仕様です。新しい予測・推薦・PDF出力機能は、まだアプリに実装していません。

狙いは、抄録や本文に含まれる課題・方法・結果・制約から研究候補を発見し、数値分析で評価したうえで、LLMが支持根拠と反証を含む評論を作ることです。ユーザーが次に調べる分野と、着手前に確かめる事項まで提示します。

| 評価軸 | 答える問い | 主な出力 |
| --- | --- | --- |
| 研究の伸び | 今後、研究する人・論文・方法の採用が増えるか | 1・3・5年先の件数／構成比の見通し、研究チームの広がり、検証成績 |
| 実用化の見通し | 用途に必要な性能・再現性・規模・コストの条件が整いつつあるか | 検証段階、裏付けのある進展、残る制約、条件付きの到達シナリオ |

論文（原文・来歴） → 事実（根拠文付き） → 計算（候補・予測） → 評論（支持・反証） → 推薦（画面・PDF）

### 計算とLLMの役割

Transformerは文献・概念の類似性と候補探索に使い、Pythonは件数・変化・比較・予測誤差を計算します。LLMは文章からの構造化と評論を担当し、計算済みの数値は変更できない構成にします。根拠に戻れることを、推薦の基本条件とします。

### 最初の到達点

新設する「有望領域の推薦」で候補を比較し、分野名をクリックすると、年次グラフ・隣接分野との比較・根拠文・反証・将来シナリオが開く構成です。同じ分析時点の結果をPDF、CSV、JSONで保存します。

論文が少ない領域は、検索範囲の不足でも生じます。希少性だけで推薦せず、技術的な接続根拠と不足情報を一緒に示します。実用化の成功確率は、検証できる教師データが揃うまで表示しません。

## 02 / EVIDENCE | 論文を、根拠付きの事実に分解する

分野共通の骨格に、材料・医学・情報などの項目を追加する

Scopusの有無に依存せず、既存のCSV・公開論文データの取り込み口を共通化します。DOI等で重複をまとめ、原文、取得元、取得日時、公開日、文献種別、検索式、収集期間を保持します。引用情報の欠測も保存します。

| 抽出する情報 | 保存する内容 |
| --- | --- |
| 課題・用途・対象 | 何を解決したいか。材料、疾患、データ、装置などの対象系。 |
| 方法・条件 | 実験／計算手法、比較対象、試験環境、測定条件、試料数。 |
| 結果・制約 | 指標名、数値、単位、誤差、改善と悪化、失敗・未解決点。 |
| 根拠と帰属 | 文献ID、原文の位置と引用文、自論文の結果か先行研究の紹介か、肯定／否定。 |
| 品質と来歴 | 実抄録／本文／生成要約、抽出モデル・版、原文ハッシュ、検証状況。 |

### 抽出の進め方

まず文献と関連箇所を埋め込み検索で絞り、LLMが上記の固定形式へ抽出します。Pythonで原文との一致、単位・数値、必須項目、文献IDを検査します。文章上の意味や否定の解釈は、分野・言語別の人手評価で確認します。科学文献の実体・関係抽出研究を参考にします。[1][2]

### ステンレス鋼の引張強度なら

対象を「鋼種・成分」、方法を「加工・熱処理」、条件を「温度・ひずみ速度・試験片」、結果を「引張強度・伸び・ばらつき」へ展開します。条件の異なる値を単純平均せず、同じ条件の比較群だけで改善量やトレードオフを計算します。ここでの項目は設計例であり、実際の有望技術の判定ではありません。

今回のCSVにあるタイトル由来のテスト抄録は、画面・取り込み確認には使えますが、実験結果や実用化段階の証拠から除外します。原文がない項目は「不明」とし、LLMによる補完を事実として登録しません。

## 03 / SIGNALS | 内容と書誌指標を組み合わせる

候補は「課題 × 方法 × 対象系」で追跡し、条件と結果を紐付ける

NMFの分野名は入口として残し、その中から具体的な研究候補を作ります。候補IDと概念の対応表を版管理し、クラスタ名の変更や分割・統合で同じ研究テーマを見失わないようにします。

| 観点 | 計算アルゴリズムと読み方 |
| --- | --- |
| 成長・急増 | 年／月の論文構成比と変化率、バースト検出。母数と観測期間を併記し、小標本の急増を区別する。[3] |
| 新しい接続 | SBERTの近傍検索、NMFの混合比、課題と方法の共起グラフ。過去文献からの距離と、近接分野での使用実績を見る。 |
| 研究の広がり | 方法の言及・実際の採用・追試を分けて集計。著者IDと共著関係から異なるチームへの広がりを推定する。 |
| 引用の広がり | 分野・公開年・種別・データ源を揃えて引用を比較。参考文献があれば、共引用・共通参考文献による接続も追加する。 |
| 技術的進展 | 条件を揃えた性能差、独立検証、耐久性、規模、費用の証拠を集計。数値が揃わないものは定性的証拠として分ける。 |

### 推薦候補を作る三つの経路

① 同じ課題に対する新手法の採用が増えている。② 複数の研究が、従来の制約の解決を報告し始めている。③ 隣接分野の方法を移せる可能性があり、対象と条件の適合を説明できる。③は特に「未検証の研究仮説」として表示します。

既存のSBERT・NMFを初期実装に使い、科学文献向けのSPECTER2等は分野・言語別の評価で改善を確認してから選択肢に追加します。科学文献用の埋め込みであること自体は、未来予測の精度を保証しません。[4]

Referencesがなくても内容・件数・共著の分析は動きます。参考文献の接続範囲と欠測率を表示し、欠測を「引用なし」と扱いません。同一機関でないことも、研究チームの独立性の証明にはなりません。

## 04 / FORECAST | 1・3・5年先を、検証できる形にする

短期の数値予測と、長期の条件付きシナリオを区別する

| 対象 | 初期モデルと出力条件 |
| --- | --- |
| 研究の伸び | 現状維持・減衰トレンドを基準とし、十分な年次データがあれば、内容指標を加えた正則化カウントモデルを比較する。 |
| 方法の採用 | 他チームの方法採用・追試を将来の観測結果として定義。教師データが揃うまでは件数・傾向の表示に留める。 |
| 実用化の見通し | 性能、再現性、実環境、規模、コスト、導入条件を別々に評価。証拠のある段階と、次段階へ進む条件を出す。[5] |

### 過去のある時点に戻って、先の結果と照合する

予測対象は、基準年から1・3・5年後の年次論文数と構成比です。学習時点より後の文献・引用・語彙・クラスタを入れず、時点を移して評価します。将来文献の割り当て規則を固定し、新分野の発見は別評価にします。現在の累積引用数は過去へ流用しません。[6]

特徴量・モデル・重みの調整は学習・検証期間内で行い、未使用の将来期間で最終評価します。データを見て成功条件を変えず、最終評価に使った期間と対象数を記録します。

| 検証すること | 評価方法 |
| --- | --- |
| 予測が役立つか | 件数のMAE、単純予測に対する改善、上位k件の適中率と取りこぼし。分野・規模・予測期間別に集計する。 |
| 内容を使う価値 | 内容のみ／書誌指標のみ／両者併用を、同じ時点と候補集合で比較する。LLMだけの候補選択も補助比較する。 |
| 不確実性 | 予測区間の実測被覆率、重み変更時の順位、時期・チーム単位の再標本化による安定性を表示する。 |

確率を出す場合は、成功条件を事前に定義した教師ラベルと、確率の校正を評価します。実用化は追跡期間が不足した事例を「失敗」とせず、未観測として扱います。論文だけでは市場規模・採算・普及率まで推定できません。

過去5年分だけでは、5年先の予測を複数時点で検証できません。古い学習期間と5年の追跡期間を別途確保します。また、最新の事前学習モデルを使う過去検証は、学習済み知識の時間的混入を明示し、厳密な当時予測と区別します。

## 05 / CRITIQUE | LLMが、根拠に沿って評論する

支持と反証の両方から、候補の強みと成立条件を整理する

LLMへ渡すのは、固定した数値、根拠文、抽出事実、収集範囲、欠測、予測の検証成績です。ローカルLLMを基本に、既存のOpenAI接続口も利用できる同一の入出力形式にします。

| 工程 | 生成・検査する内容 |
| --- | --- |
| 1. 支持側の検討 | なぜ今注目するのか。観測された進展と数値を、文献ID・事実ID付きで説明する。 |
| 2. 反証側の検討 | 対立する結果、同一チームへの偏り、試験条件の違い、実用化の障害を追加検索して評価する。 |
| 3. 統合評論 | 分野全体の状況、候補の位置付け、推奨する研究課題、成立条件、次に必要な実験・文献をまとめる。 |
| 4. 検査と表示 | 数値・根拠の参照先・引用文を照合。未裏付けの主張を保留し、事実／推論／仮説を明示する。 |

### 推薦カードの必須項目

研究テーマ、研究の伸び、実用化の証拠、推薦理由、反証・弱点、未取得情報、次に試すこと、1・3・5年の見通しを並べます。見通しは基準・進展・停滞のシナリオと、その分岐条件を示します。根拠のない到達年は決めません。

### ステンレス鋼を想定した表示の型

設計例・実際の分析結果ではありません。
候補：特定鋼種における加工と熱処理の組合せ。
推薦に必要な根拠：強度と伸びの両立、条件を揃えた比較、別チームの再現。
反証の確認：腐食・疲労・加工性への悪影響、試料規模や設備の違い。
次の研究：条件を固定した追試と、用途に必要な特性の同時評価。

推薦順位は二つの評価軸と根拠の充足度を確認して決めます。どの軸を重視するかを表示し、重みを変えると順位がどう動くかも確認できます。研究探索向けと実用化検討向けを切り替えますが、未検証の成功確率に換算しません。

LLM同士の同意を検証済みの根拠とはしません。専門家による根拠への忠実さ・反証の見落とし・提案の妥当性の評価を、予測精度とは別に記録します。LLM未接続時も数値と根拠一覧は閲覧できます。

## 06 / EXPERIENCE | 有望領域の推薦を、専用画面にする

NMFの分野名から、比較・評論・根拠へ進める

画面構成案：二軸マップと候補詳細パネル。研究の伸び、実用化に向けた検証段階、支持・反証、年次推移、隣接分野、将来シナリオ。実データの分析結果ではありません。

上図は画面構成案です。実装済み画面や実データの分析結果ではありません。縦軸は検証証拠の段階を示し、商用化の確率は示しません。段階不明の候補は別枠に表示します。

| 表示 | 操作すると分かること |
| --- | --- |
| 二軸マップ | 横軸：研究の伸び。縦軸：用途別の検証段階。予測が出ない候補は別枠。点を選ぶと証拠の内訳が開く。 |
| 分野の詳細 | 論文数・構成比・方法採用の年次推移、主要チーム、技術結果、残る制約、分野全体の評論。 |
| 隣接分野との比較 | 二分野の年次系列、共著者の活動先の変化、方法採用、所属・試験条件の違い、引用方向と根拠文。 |
| 推薦と将来像 | 今取り組む理由、反対材料、条件付きシナリオ、次に調べる文献・実験、分析の限界。 |

研究者が両分野へ論文を出したことは「研究活動の移動」として表示し、所属の移籍と混同しません。引用や時系列の前後関係だけでは、分野間の因果的な影響を断定しません。従来のNMF配置図はテーマの近さを見る別の図として残します。

縦軸は、用途ごとの必須証拠が揃った段階を示します。最も進んだ一論文で全体を格上げせず、未検証の項目と相反する結果を併記します。用途や判定基準が違う候補は、同じ段階として直接比較しません。

フィルターは期間・データ源・研究探索／実用化検討・証拠充足度。将来、保有設備や予算も任意指定できる構成にします。指定がない場合は一般的な研究候補として提示します。

## 07 / IMPLEMENTATION | 既存アプリに、評価結果の保存層を加える

数値・評論・PDFが同じ分析時点を参照する構成

Python側に事実抽出、指標計算、候補評価、評論検査、PDF生成を追加します。既存の取り込み・NMF/SBERT・共著ネットワーク・ジョブ処理・LLM接続を再利用し、HTML/JavaScript側に推薦ページと詳細パネルを加えます。

| 保存単位 | 主要項目 |
| --- | --- |
| content_facts | paper_id、原文ハッシュ、根拠の位置と引用文、課題／方法／結果／制約、モデル版、検証状況。 |
| assessment | result_id、分析基準日、資料一覧と収集範囲、候補ID、指標と欠測、順位・重み、モデル版、検証成績、判定保留理由。 |
| commentary_revision | assessment_id、数値ハッシュ、モデル・プロンプト版、生成日時、支持・反証・推薦・シナリオと根拠ID。 |
| report_snapshot | 評価ID＋評論版、図表データ、テンプレート版、生成日時、PDF/CSV/JSONの対応関係。 |

### 追加APIの案

POST /api/assessments：既存の分析結果から抽出・評価ジョブを起動。
GET /api/assessments/{id}：進捗、数値、根拠、欠測を取得。
POST /api/assessments/{id}/commentaries：モデルを選んで評論版を作成。
GET /api/assessments/{id}/export：指定版をPDF・CSV・JSONで出力。

### PDFレポートの内容

要点と推薦候補、二軸マップ、分野・隣接分野の推移、候補別の支持と反証、将来シナリオ、出典、方法と制約を固定テンプレートへ流し込みます。Pythonで日本語フォントを埋め込み、図は印刷で読める品質にします。

出力時にLLMへ再生成を依頼せず、画面で見た評論版と数値をそのまま使います。CSVは候補指標・年次推移・事実・評論を別表で保存し、長文と改行を適切に引用します。JSONには完全な構造と来歴を保存します。

LLM接続失敗や一部文献の抽出失敗は、処理状態と対象件数を表示します。数値のみのレポートも出力でき、評論が生成されたように見せません。根拠文中の指示文は資料として扱い、実行指示として処理しません。

## 08 / DELIVERY | 根拠を整えてから、予測の性能を確かめる

機能追加の順序と、公開できる結果の条件

| 段階 | 作るもの | 完了を確認すること |
| --- | --- | --- |
| 1. 根拠と評論 | 事実抽出、支持・反証の評論、詳細画面、PDF/CSV保存。 | 数値と原文へ遡れる。生成抄録を除外。接続失敗と日本語PDFを確認。 |
| 2. 候補の推薦 | 内容の接続候補、二軸評価、隣接分野の比較、順位の感度表示。 | 順位の理由と欠測が分かる。希少性だけで有望と判定しない。 |
| 3. 予測の検証 | 時点を分けた評価、1・3・5年の予測、モデル比較。 | 単純予測との比較を期間別に公開。改善しないモデルは採用しない。 |
| 4. 実用化情報 | 特許、実証、規格、製品・コスト等の外部証拠を用途別に接続。 | 出典と時点が追える。予測確率の導入は教師データと校正評価後。 |

### 入力データによる動作の違い

| データの状態 | 利用できる分析 |
| --- | --- |
| 単一年・生成抄録 | 取り込み・件数・語句マップの確認。内容に基づく効果判定と未来予測は保留。 |
| 複数年・実抄録 | 内容の接続、研究の伸び、支持・反証の評論。収集範囲が不明なら標本内の傾向として表示。 |
| 本文・条件・実測値あり | 条件を揃えた比較と制約の評価。抄録から欠落していた情報を補える。 |
| 長期履歴・外部証拠あり | 長い予測期間の検証、実用化段階の追跡。実際の検証成績に応じて予測を提供。 |

月次の急増には実際の公開月が必要です。年しかない文献に便宜的な月を付けず、未収集期間はゼロ件にしません。最新の年・月が途中なら、完了した期間と区別します。検索式・取得上限・収集率を記録し、母集団が不明なら未収録率も不明とします。

毎年上位100件だけを取得した資料など、収集上限や検索順位により期間間の比較が成立しない場合は、分野全体の成長予測を保留して探索・記述に限定します。基準を満たす追加データでのみ予測を有効にします。

既存の年次件数の外挿は、そのまま内容予測の性能を示すものではありません。今回の追加で、論文内容が予測に寄与したかを別途検証します。現在のダミー100件だけでは、実用化や5年先の妥当性を確認できません。

## 09 / METHODS & SOURCES | 指標の定義と、設計の参考文献

参考研究の成果を、このシステムの性能と取り違えない

### 初期の計算仕様

分野内構成比 s(t) = 候補の該当論文数 n(t) / 同じ検索範囲の全論文数 N(t)。複数候補への所属は許容し、候補間の構成比の合計を100%と解釈しません。N(t)が不明・未観測の場合は構成比を計算しません。

成長は複数期の構成比と件数を併記し、小標本の比率には縮約と感度確認を用います。新規性は、当該時点より前の文献に対する埋め込み距離などで測ります。距離は意味上の珍しさであり、技術的価値の尺度とは限りません。

根拠充足度は「有効な原文あり／条件あり／比較対象あり／独立検証あり」等の項目別に表示します。総合順位を出す場合は指標の正規化・重み・欠測時の扱いを版管理し、データ源や重みを変えた順位変動を併記します。
