# 全件抄録レポート

Research Atlas v2.5の「全件レポート」は、選択した分析結果の全論文を処理台帳に登録し、収録された抄録の内容を順次分析する機能です。20,000件のうち代表論文だけを選ぶ処理とは別に、全件を対象にします。総件数の固定上限はありません。LLMの処理速度、抄録の長さ、ディスク容量によって所要時間と処理可能量が変わります。

## 利用手順

1. ScopusなどのCSVを取り込み、対象期間と分類方法を選んで分析します。全件レポートの範囲はこの分析結果です。インポート済みでも分析期間から外した論文は含みません。
2. ブラウザの接続設定で、ローカルLLMまたはOpenAI APIを設定します。新機能も既存のブラウザ保存設定を使用し、APIキーやProxy情報を台帳・`.env`へ保存しません。
3. 「全件レポート」を開き、接続先を選んで100件で試します。全論文の台帳を用意した後、指定した件数の未処理抄録を抽出します。抄録のない論文は「欠測」に分類します。
4. 進捗、根拠抽出の内容、警告、実測した抽出時間を確認します。残り時間は処理済み論文の平均時間を用いた目安です。後続論文の長さ、分割数、LLMの負荷で変わり、評論生成の時間は別途必要です。
5. 指定件数ずつ「再開」するか、「全件連続」を選びます。1回の指定件数は1〜20,000件ですが、全件連続モードは登録された残り全件を対象にします。サーバーが起動していればタブを閉じても処理は続きます。PCのスリープ中は進みません。
6. 一時停止は現在のLLM応答を保存してから反映されます。アプリやPCを再起動した場合は、同じ分析結果の全件レポートを開き、保存済みのレポートを選んで再開します。接続設定は再開したブラウザから受け取ります。
7. 「評論を生成」で抽出済みの全結果を年別・分野別に統合し、全期間の評論を作ります。未処理・失敗・欠測がある場合は部分レポートとして明示します。追加抽出後は評論を更新してください。
8. PDF、CSV、JSONを保存します。出力操作自体はLLMを呼び出さず、保存済みの内容を出力します。

## 全件を処理する仕組み

```text
分析対象の全論文
  ├─ 抄録なし → 欠測として記録
  └─ 抄録あり → 全文を分割して逐次処理
                  → 目的・材料・条件・手法・結果・限界・否定結果
                  → 原文引用・文字位置・数値／単位・照合警告
                         ↓
             Pythonによる年・分野・手法集計
                         ↓
             全抽出結果から段階的なLLM要約
                         ↓
             年別・分野別の評論 → 総合評論
                         ↓
                PDF + 全件CSV / JSON
```

抄録の入力容量が足りないときはさらに分割します。短縮した入力を元の抄録全体の処理完了として数えません。分割範囲は原文の文字位置として保存し、途中まで成功した範囲を再開時に利用します。モデルの入力枠が指示と回答形式すら収められない場合や、不完全な回答を繰り返す場合は失敗として残ります。

抽出された引用は、送信した原文中に実在する連続した文字列かを確認します。一致しない引用は根拠として採用しません。原文の数値・単位と要約に不一致がある場合は、生成文を警告付きで保持します。これは科学的な意味、実験設計や因果関係の妥当性まで検証する仕組みではありません。

各論文の抽出結果を入力上限内の小さな単位に分けて要約し、その要約をさらに統合します。全入力がこの処理を通ったことと、最終文章が全ての論点を保持していることは異なります。否定結果・限界の抽出記録も、圧縮された評論とは独立して保持します。元の論文IDと原文引用まで遡って確認してください。

## 計算結果と評論の区別

| 項目 | 内容 |
| --- | --- |
| 年・分野の件数 | 台帳に登録した全対象論文をPythonで集計。抽出成功数・欠測数・失敗数・未処理数を併記 |
| 手法の頻度 | LLMが手法として抽出した表記を正規化し、その表記のある論文を数える。同義語の意味的な統合は保証しない |
| 年別・分野別評論 | 全抽出結果を段階的にLLMへ入力し、研究対象・手法・成果・相違・限界を論じる |
| 総合評論 | 年別の評論を統合して時系列の移り変わりや将来の研究仮説を論じる |
| 将来の見通し | 根拠付きの仮説。研究の伸びと実用化の見通しを区別し、成功確率やTRLを確定しない |

取得元や年ごとの収録率が違えば、論文数の増減にその違いも影響します。件数が多いことだけから研究の優劣や実用化を断定しません。既存の「有望領域」タブのRocchio機能は別であり、初期分析10,000件までという制約をこの機能追加で変更するものではありません。

## 保存と再開

保存先は **`data/corpus_reports.sqlite`**（`ATLAS_DATA_DIR`指定時はその配下）です。元のCSV、データセット、分析結果は変更しません。台帳には論文の処理状態、抽出記録、引用、分割範囲、集約・評論、モデル名と処理バージョンを保存します。通常のデータと同様、バックアップの対象にしてください。

同じ抄録と生成条件で完了した抽出はキャッシュから再利用します。入力やモデル・処理バージョンが変わった場合は再処理します。モデルファイルを同じ名前で差し替えたことまでは検出できないため、異なるモデルには異なるモデル名を使用してください。別のモデルや接続先へ切り替える場合は、新しいレポートとして作成します。

抽出・評論の途中経過を保存します。一時停止や再起動後は保存済み部分を使って再開します。LLMへの接続障害が続く場合は停止し、接続を直してから失敗分を再試行できます。API認証情報やProxy認証情報は保存しません。

## LocalLLMの時間切れへの対応（v2.5.1）

全件レポートでは、実際に成功したLLM呼び出しの時間と入力量を記録し、次の入力サイズを調整します。1回約120秒を目安に上限を下げますが、モデルの読み込み時間・出力の長さ・負荷でも速度は変わるため、2分以内の完了を保証するものではありません。キャッシュを読んだだけの処理は速度の計測に使いません。調整値は同じレポート・接続先・モデルにひも付けて保存し、アプリを再起動しても再開時に利用します。

評論の入力サイズは速度調整の目安です。中間要約の統合が進まなくなる場合は、必要最小限の要約を目安より大きな入力で統合します。その場合も実際のモデルの入力容量を確認し、時間切れの回数制限を適用します。

時間切れが起きた抄録の範囲、または評論の入力は、さらに小さく分割して再試行します。両側の内容を処理し、省略した範囲を完了には数えません。最小の入力まで小さくした場合は同じ入力の再試行を1回まで行います。時間切れへの自動対処は、1論文の抽出または1区分の評論の実行につき合計3回までです。上限に達したら次の論文・区分へ進まず、レポートを一時停止します。中間要約や完了した抄録の範囲は保持されます。

- 抽出を再開する場合は、LLMの状態を確認して「失敗した論文を再試行」を押します。
- 評論を再開する場合は、再度「評論を生成」を押します。保存済みの要約・分割計画を使い、未完了部分から処理します。
- ユーザーが明示的に再試行した実行には新しい自動対処枠を用意します。自動で何度も全ジョブを再起動することはありません。
- 接続失敗・認証失敗・メモリ不足は、入力の再分割で解決する時間切れとして扱いません。抽出が3論文、または評論が3区分続けて失敗した場合も一時停止します。

1回のLLM呼び出しの制限は、最初の受信まで10分、受信開始後の無通信3分、生成全体20分です。レポート全体の時間制限ではありません。画面には現在の入力上限と時間切れへの累計対処回数を表示し、調整記録はCSV／JSONにも保存します。既存の重心評論などの待ち時間やプロンプトは変更しません。

## 出力

| 形式 | 収録内容 |
| --- | --- |
| PDF | 対象範囲、処理件数、警告、年次グラフ、年・分野集計、手法頻度の上位30表記、総合評論、保存された全区分の評論。全論文の原文を並べた文書ではない |
| CSV | レポート情報、集計、評論、論文ごとの状態、全抽出根拠、数値・単位、原文引用、文字位置、分割処理の記録。`row_type`で行の種類を区別 |
| JSON | レポート・集約・評論と全論文の抽出記録。階層要約の入力対応や否定結果も保持 |

CSVの`paper`行は抽出根拠がない論文にも作成し、`fact`行は抽出された根拠ごと、`chunk`行は分割された入力範囲ごとに作成します。`review`・`review_section`・`review_sources`は評論と根拠の対応です。原文位置`source_start`・`source_end`は0から数え、終了位置は含みません。Excelで数式と解釈され得る文字列は安全な文字列として出力します。

PDFには日本語TrueTypeフォントが必要です。Windowsでは利用可能なMeiryoを確認し、使えない場合は`ATLAS_PDF_FONT`にフォントのパスを指定します。

## 対象範囲の読み方

- **抽出済み**：対象抄録の全範囲の処理が完了し、原文と照合できる根拠を得た論文数。数値・単位についての警告や、抽出できた論点の範囲も確認してください。
- **抄録なし**：書誌情報はあるが内容分析に使える抄録がない論文数。
- **失敗**：必要な範囲を処理しきれなかった、または全範囲を処理しても原文と照合できる根拠を得られなかった論文数。一部の抽出結果が保存されている場合があります。
- **未処理**：これから処理する論文数。中断した論文の未完了部分も含みます。
- **処理文字数**：入力として処理された抄録の範囲。抽出・引用・最終評論に採用された文字数ではありません。

20,000件に対する構造的な動作確認には模擬LLMを使用します。実機LLMで20,000件を処理した時間・費用や科学的な抽出精度の保証はありません。実データでは最初の100件の内容と時間を確認してから規模を広げてください。
