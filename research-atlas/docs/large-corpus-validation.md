# 大規模CSV・多年分析の検証記録

検証日: 2026-09-15。合成データで容量とデータ保持を確認した記録です。実論文のテーマ分類精度・予測妥当性を示す評価ではありません。

## 容量と使い方

- 1ファイル20,000行、ファイル容量の固定上限なし。複数CSVを選択して順番に統合します。
- 「保存のみ」で蓄積し、重複統合後200,000論文まで保存できます。既存の版は保持されます。
- 蓄積後、分析期間（最大50暦年）とNMF・LDA・K-meansなどの手法を選びます。
- 年別件数、引用集計、テーマ分類は対象全件。地図は最大400論文の代表標本です。
- 文献一覧は全件検索とページ取得、抄録は個別取得です。JSON出力には全件を含めます。
- Sentence-BERT / Transformer / BERTopicの意味表現は20,000件、有望領域のRocchio反復探索は10,000件までです。これらは期間を絞った分析で利用してください。

## 実測

Windows、16 GB RAMの開発機で実施しました。NMF測定はBLAS等のネイティブスレッド数を2に制限しています。同じPC上の他の処理やディスク状態で時間は変動します。

| 検証 | 結果 |
| --- | --- |
| 180,000件に20,000件を統合 | 200,000件、180.83秒。元データ・参照情報を保持 |
| 200,000件・2000～2025年のNMFを全件実行 | 分析363.77秒（約6分4秒） |
| NMF全件学習・分類 | 6,000語彙、12テーマ、3周の全件学習、全200,000論文の所属度を算出 |
| 全件の集計整合性 | テーマ件数合計・年別件数合計が200,000、26年、地図400論文 |
| 分析ワーカーの最大ワーキングセット | 1,353,650,176 bytes（約1.26 GiB） |
| 全分析結果をJSON化したサイズ | 334,878,859 bytes（約319 MiB） |
| 実ブラウザからの複数CSV取込 | 20,000件＋5件（2件重複）→20,003件。保存後、26年分のNMF画面を表示 |

NMFの合成抄録は英語700文字、12分野の定型文に語彙変種を追加したものです。1論文につき著者1人・参照1件、全体で2,000著者としています。実データは抄録の長さ、語彙、所属・著者数、参考文献数が異なるため、必要メモリ・保存容量・時間が大幅に増える場合があります。上表は必要RAMの下限や処理時間の保証ではありません。

別の200,000件の保存用合成データでも、SQLite保存後の取得と全件JSON出力を確認しました。この保存試験のテーマ重みは人工的な値で、上表のNMF推定値とは別です。

| 保存済み200,000件のAPI処理 | 実測 |
| --- | --- |
| 概要取得（代表論文405件と全件集計） | 0.35秒 |
| 年・引用・タイトル順の先頭／末尾ページ | 0.09～1.36秒 |
| 抄録・タイトル等の部分一致検索 | 1.28～3.36秒 |
| 全件JSONのストリーミングと内容照合 | 200,000件すべて一致、約296 MB、約45.6秒（検証処理を含む） |
| 上記取得・出力試験の最大ワーキングセット | 約156 MiB |

初回保存時に一覧用の索引を作成します。以前の形式で保存した大規模データは、初回の一覧表示時に索引を準備するため時間がかかります。保存中は処理を完了させてからアプリを終了してください。

## CSV容量制限の撤廃

v1.8.1では20 MB・256 MBといったCSV容量の固定上限を廃止しました。270,597,837 bytes（約258 MiB）の合成CSVをローカルHTTP経由でアップロードし、5,000行すべての取込が成功することを確認しました（約14.7秒）。この容量試験では未使用列を埋めた合成データを使用しています。アップロード先の一時ファイルから順に読み込み、文字コードの検証でもファイル全体をメモリ上へ複製しません。正規化後の論文データと分析には引き続きメモリが必要です。

## 保存と応答

大きな集合では抄録をSQLiteに分離し、同じ内容の論文を複数の保存版で共有します。各版の論文の対応表を保持するため、追加後も元の分析を再現できます。ブラウザ向けの応答と根拠一覧だけを制限し、集計値・保存データ・全件エクスポートは保持します。

バックアップはアプリ停止後にデータフォルダー全体をコピーしてください。管理用JSONだけでなく、`large/papers.sqlite3` と補助ファイルも必要です。LLM・proxyの設定は従来どおりブラウザに保存します。
