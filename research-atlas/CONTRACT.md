# Research Atlas implementation contract

Local FastAPI + plain HTML/CSS/JS application. All labels/help are Japanese with restrained English design accents. No external frontend CDN. Python does numerical analysis. `data/` persisted locally and ignored by git.

## Landscape relief and contours

- `GET /api/results/{result_id}/terrain` reads an existing saved map, then returns `{version:1,grid:{width:49,height:33,values:[row-major density]},contours:[{level,paths:[[[x,y],...],...]}],node_heights:{paper_id:height},meta}` without modifying results. Empty maps return zero grid/no contours. Cache bounded32 by normalized paper IDs/coordinates, with response copies.
- Python `app/map_terrain.py` uses equal-weight Gaussian KDE on at most400 projected papers, bandwidth0.075 in normalized coordinates. Density is divided by its grid maximum, not total corpus size or citations. Marching squares with a saddle decider produces eight levels0.12..0.96; closed paths repeat their first point and boundary paths remain open. Node heights use bilinear grid sampling; the drawing approximates the surface with triangles.
- `static/map-terrain.js` renders inert SVG terrain and shared flat/relief projection. `static/landscape.js` integrates existing clickable paper nodes and topic labels, live height/contour/mode controls, scoped async loading/retry, bounded8-result browser-memory cache and retained zoom. Density is requested once per result, not on every display adjustment. Both overview and technical map use the same data. Browser connection settings are unchanged.
- Height is relative visual density in a 2-D projection, not an independent 3-D embedding, forecast, maturity, research scarcity or importance score. Existing maximum400 display sampling limitations apply. Highlighting a topic/recent papers never changes the density population.

## Browser connection settings (v1.7)

- `static/connection-settings.js` owns `research-atlas.connections.v1` in localStorage per browser profile/origin. Save, clear, cancel and draft connection checks are separate from analysis submission; save/clear updates status without reanalysis. Cross-tab storage events propagate changes; status refreshes reject stale responses. Secret fields are masked in the form, but localStorage is plaintext.
- Schema: `{version:1,openai:{api_key,model},local:{backend:'ollama'|'openai_compatible',url,model,api_key},proxy:{enabled,url,username,password,no_proxy}}`. Empty OpenAI credentials and local Ollama at `http://127.0.0.1:11434` are defaults. Inputs are bounded and validated before browser save and again in Python.
- `AtlasConnections.fetch` attaches UTF-8 JSON encoded as base64 in `X-Atlas-Connection` (max 16384 characters) only to same-origin `/api/` requests; redirects are rejected. Python parses a frozen settings model into a ContextVar. Every executor submission captures the caller context in `app/job_context.py`; ongoing jobs retain their starting settings. Credentials are never put in job/options/result/export data or written to `.env`.
- `GET /api/connections/status` returns redacted browser configuration status. `POST /api/connections/test` accepts `{target:'openai'|'local'|'proxy'}` and returns `{ok,target,message}` using the supplied header, without persisting it. Checks use a fixed OpenAI model-information GET, local model listing or a fixed Crossref GET; no papers or generation requests.
- LLM credentials and proxy configuration never fall back to environment variables. SDK organization/project/custom-header defaults are neutralized per client without changing process environment. Shared HTTP transport uses explicit proxy authentication and host/domain/IP/CIDR/port exclusions, `trust_env=False`, no redirects. Public sources, Scopus and OpenAI use browser routing; local LLMs always connect directly to loopback. Embedding model downloads and other non-LLM server settings remain separate.

## Content exploration and Rocchio extension (v1.6)

- The new `有望領域` tab initializes candidates from classified existing topics, retaining all papers but excluding unclassified topics from recommendations. It presents initial-cohort annual descriptions, content evidence, retrieval recommendations, feedback, query previews, round history, optional commentary, and PDF/CSV/JSON exports. It does not implement a trained future-growth forecast or predict commercialization probability/TRL.
- `app/foresight.py`: `build_assessment(result)->dict`; `refine_assessment(assessment,candidate_id,feedback,incoming_papers=None,embedding='tfidf')->dict`. Inputs remain unchanged; the core makes no external retrieval/LLM calls. Assessment includes `schema_version`, `result_id`, `dataset_id`, `meta`, `papers`, `candidates`, `rounds`, `feedback`, `retrieval_space`, `warnings`. Saved versions add `id`, `parent_id`, `revision`, `created_at`, `numeric_hash` under `data/assessments/`.
- Candidate IDs match topic IDs. Each retains `original_query`, `seed_terms`, `seed_paper_ids`, `seed_count`; updated `terms`, `paper_ids`, `provisional_paper_ids`, `count`, `growth`, `readiness`, `evidence`, `recommendations`, `retrieval`, `stance_feedback`, and deterministic `commentary` describe exploration. Automated evidence IDs identify fragments; each fragment has its own `paper_id`. Do not confuse fact IDs with bibliographic IDs.
- Rocchio uses a fixed original query, cumulative candidate/paper feedback with latest explicit judgement, coefficients original 1.0 / relevant mean 0.75 / explicit irrelevant mean -0.25 / provisional relevant mean 0.10. Support/counterevidence is a separate attribute and never determines the subtraction sign. Pseudo negatives cannot subtract or overwrite explicit feedback. An update is reduced when original-query cosine would fall below 0.80. TF-IDF clips negative coordinates and freezes the initial vocabulary/IDF; English words/bigrams and Japanese character 2/3-grams are lexical matching, not synonym resolution.
- Initial assessment uses TF-IDF; refinement optionally uses locally cached SBERT with existing token-window pooling. No model download or silent fallback occurs in exploration. Relevance/distance are cosine-based. Recommendations require positive similarity and original-query cosine >=0.04; up to 300 papers are reranked with an explicit shared-author penalty and 30 displayed. This is retrieval ranking, not a promise of technical value or proof of team independence. Up to 20 high-similarity retrieved papers may become provisional evidence without changing original topic assignments.
- `growth.series` uses the frozen initial paper/year snapshot and seed membership; incoming retrieval cannot rewrite its counts or denominator. Growth is descriptive of the initial imported corpus only. Single-year data, capped samples, synthetic/test input, absent comparison periods, or adaptive additions withhold the growth decision. All candidates retain `forecast=[]`, `forecast_available=false` and an explicit unimplemented-model reason, regardless of existing result forecasts.
- `readiness.evidence_coverage_score` is the percentage of six dimensions with an eligible abstract mention: performance, reproducibility/validation, real environment/prototype, scale/manufacture, durability/safety, cost/resources. It is not a maturity score, official TRL, or success probability. `stage='unassessed'`; missing evidence remains unknown, not failed. Generated/test abstracts are excluded. Full candidate-level paper counts accompany at most 120 fragments with exact character offsets, abstract hash, dimension, numeric mentions and heuristic stance; attribution and scientific meaning remain unverified.
- `app/foresight_sources.py` owns query construction and external retrieval. Query previews retain the original seed group plus updated terms. Europe PMC/arXiv/Crossref use public adapters; Scopus Search uses `ELSEVIER_API_KEY` (alias `SCOPUS_API_KEY`) and optional `ELSEVIER_INSTTOKEN` only in authentication headers. Configured availability is not verified entitlement. COMPLETE may fall back to STANDARD with missing-abstract warnings. Search never fabricates reference lists or annual citation histories. All retrieval reports retain actual queries, dates, per-year coverage, source provenance and adaptive-sampling limitations. Existing `merge_papers` checks the final 10,000-paper limit after deduplication and preserves citation-source separation.
- Initial public search queries are retained as a portable Boolean tree (words/phrases/AND/OR/parentheses), unioned across initial sources, then intersected with candidate terms. Unsupported field/NOT/wildcard syntax fails explicitly. All providers apply the initial condition again to visible title/abstract/keywords; record API retrieval count separately from accepted count and exclusions. Missing abstracts, abbreviations and synonyms can produce conservative false negatives. Round-generated queries cannot replace the initial scope.
- `POST /api/assessments {result_id}` starts a job; poll `/api/jobs/{id}` for `assessment_id`. `GET /api/assessments?result_id=...` lists saved versions; `GET /api/assessments/{id}` reads one. `GET /api/assessments/{id}/queries?candidate_id=...` previews queries without retrieval. `GET /api/foresight/status` exposes configured providers, local/OpenAI availability, embedding dependencies and PDF availability without credentials.
- `/?result_id=...&assessment_id=...&view=foresight` restores a saved result and assessment via API, validates matching ownership and the original dataset, and restores analysis options without recomputation. Missing/mismatched identifiers produce a visible error; stale responses cannot change state or URL. New analysis clears old restore identifiers. Links depend on this local server and its persisted data.
- `POST /api/assessments/{id}/explore` accepts `{candidate_id,mode:local|external,provider:europepmc|arxiv|crossref|scopus,max_rounds:1..3,limit:20..100,embedding:tfidf|sbert,feedback:[{paper_id,relevance:relevant|irrelevant|unknown|unjudged}]}` with <=100 feedback items. The public feedback UI/API judges relevance only; internal evidence stance is distinct. Each successful round saves a new immutable version. External pre-query refinement and post-retrieval recomputation use the same parent to record one update per round. Unchanged top recommendations with no additions stop early; failures retain the latest saved version. Synthetic/test assessments reject external real-paper mixing.
- `POST /api/assessments/{id}/commentaries {candidate_id,provider:none|local|openai,model?}` optionally runs two-stage extraction then critique using existing local/Ollama/OpenAI connection rules. Send <=12 papers (title <=350 characters, abstract prefix <=2400), <=32 extracted facts and bounded scope metadata. Synthetic/test assessments and missing/test abstracts cannot supply LLM effect evidence. Check exact contiguous quotes, supplied paper/fact IDs, supported numeric tokens/signs/recognized units and required support/counter/outlook/next_steps sections; headlines, titles and caveats receive numeric checks too. These are mechanical checks, not semantic/causal/scientific verification. Numerical growth/readiness blocks are immutable; model/prompt/input hashes and generated facts are versioned separately. Refinement removes stale generated narratives/facts.
- `GET /api/assessments/{id}/export?format=json|csv|pdf&candidate_id=...` renders a saved snapshot without LLM regeneration. JSON retains structure; UTF-8 BOM CSV flattens JSON Pointer paths, types and values with formula protection; Japanese PDF uses reportlab and an embedded TrueType font (`ATLAS_PDF_FONT` override). Failed optional generation does not prevent numerical exports. Dataset switches and stale asynchronous responses cannot replace the active assessment in the GUI.

## Scopus CSV compatibility repair (2026-09-14)

- Incomplete full-name columns must not discard authors when short-name and ID lists align. Enrich by explicit embedded ID; do not guess the positions of incomplete names.
- A leading `[TEST SUMMARY; TITLE-BASED; JA]` is test metadata. Keep the raw abstract, remove only this prefix for text features and co-occurrence, flag the dataset as containing synthetic/test data. This marker does not prove bibliographic identities are fictional.
- Dataset summaries include initial analysis years: declared search scope first, otherwise observed CSV years, bounded to API limits. Importing papers applies them and clears a stale monthly anchor; citation-history additions retain selected conditions.
- A single selected calendar year has no comparable annual growth or publication forecast. Counts, maps, field reports and author networks remain available; unknown publication months remain unknown.
- For a corpus with no declared collection scope and only one actual publication year, the API derives `single_year_corpus=true`; expanding the selected years cannot reinstate growth/forecasts or inflate publication momentum. `meta.annual_comparison_available` explains availability to the GUI. Declared public-search windows retain observed zero years.
- Source-report UI must tolerate an absent initial dataset/result. Fetch connection failures explain local startup; HTTP validation details remain intact.

## Author network clustering extension (v1.5)
- `app/author_network.py`: `build_author_network(papers, group_by='community', topics=None)` returns `{nodes,edges,clusters,group_by,truncated,stats,warnings,methodology,export_data}` without mutating source papers. Grouping is `id|name|institution|community|topic`. Identity remains constant across grouping modes: explicit IDs and explicit aliases take precedence; differing explicit IDs never merge on name alone. Missing-ID exact-name matching is an estimate and must not join an ambiguous name to one known author.
- Each node retains legacy fields plus `original_ids`, `names`, `identity_basis`, `paper_ids`, `affiliations`, `original_affiliations`, `cluster_id`, `citation_known_papers`. Unique paper membership drives counts; self-coauthor edges and duplicate same-paper counts are excluded. Each edge carries full `paper_ids` for its observed shared publications.
- Name groups are candidate display groups, not identity merges. Institution groups use only explicitly author-linked affiliations; paper-wide affiliations never propagate to all authors. Preserve raw affiliation names and paper evidence. Multiple affiliations use most frequent institution with stable ties as the display group, with all affiliations accessible. Missing is unknown, not a guessed university.
- Select top 120 canonical authors by paper count/ID for layout. Weighted greedy modularity communities use all coauthor edges among those authors, before display truncation to 240 edges. Clusters contain displayed author/paper IDs and counts. `stats` identifies the displayed-author scope for edges and clusters; full-corpus author counts remain separate. Coordinates are finite normalized display positions, not quantitative measures of research distance.
- `export_data.authors` includes all canonical authors; community assignments for undisplayed authors are null. `export_data.edges` retains all edges within the 120-author population, `export_data.clusters` all display groups. Exports clearly retain their analysis scope, matching method and paper IDs.
- `POST /api/author-networks` accepts `{result_id,group_by}` and returns `{job_id}`; poll jobs for `author_network_id`. `GET /api/author-networks/{id}` reads a separately saved immutable result. `GET /api/author-networks/{id}/export?kind=authors|edges|clusters` exports UTF-8 BOM, formula-safe CSV. The original topic analysis remains unchanged. Any build/save failure terminates the job without leaking unexpected exception details.
- GUI group selection recomputes only the network; stale results cannot replace a newer dataset/selection. Cluster filters, author-name/ID/institution search, evidence details and CSV downloads share the active network. Old stored analyses can use the new endpoint without re-running embeddings.
- Ingestion/merging preserves distinct same-name explicit IDs. Author-affiliation entries with a mismatching explicit ID never fall back to name matching; explicit name-only entries still work when unambiguous. Previously stored incorrect aliases cannot be retroactively resolved without original source data.

## Field intelligence extension (v1.4)
- Classified field titles open comprehensive field/neighbor reports; paper points retain paper detail. NMF stores normalized document component weights (`paper.topic_weights`, residual unassigned mass) and full-corpus topic centroids/cosine pairs in `result.field_geometry`. Never use 2D map distance for field adjacency. Old results/other models explicitly use representative-keyword Jaccard. Default comparison selects the highest positive similarity; all zero/missing means no automatic neighbor.
- `app/field_analysis.py`: `build_field_report(result, topic_id, neighbor_id=None)` returns immutable-input comparison: focus/neighbor summaries, neighbors, annual publication counts, shared authors, observed author first-year sequences, bridge papers (both NMF component weights >=0.10), actual cross-field references, affiliation and method-mention counts, shared/distinct keywords, deterministic observations, scope/limitations and evidence papers. Forecasts reuse stored scenarios (maximum 3 years), never generate new numerical forecasts with LLM.
- Author direction only means first observed publication year within this corpus; same-year has no direction. Explicit author IDs/aliases take precedence, ambiguous name aliases do not merge distinct IDs. No claim of employment change, migration, causation, or technology transfer. Method counts match a finite vocabulary in abstracts; negation/prior-work mentions can match. Institutions are explicit metadata counted once per paper, not inferred author affiliations.
- UI lists are bounded and carry totals/display limits; `export_data` retains all neighbor/author/transition/bridge/citation/institution/method rows. `evidence_papers` is capped at 40 with abstract excerpts up to 4000 characters; the source-paper CSV independently exports every paper in both fields with full stored abstracts. Missing comparison counts remain null, distinct from observed zero.
- Bibliography metadata: `affiliations:[str]`, optional explicit `authors[].affiliations`, `references:[{doi?|id?}]`, `references_status:provided|not_provided`. Preserve standardized DOI/Scopus/arXiv/PMID/PMCID identities; arbitrary provider reference keys and availability flags are not citation links. Import, public-source parsers, merges and analytical normalization retain metadata. Discovery cache requires `metadata_pipeline_version=3`; existing data/results are unchanged until newly imported/retrieved/analyzed.
- `POST /api/field-reports` accepts `{result_id,topic_id,neighbor_id:null,provider:none|local|openai,model:null}` and returns `{job_id}`. Poll `/api/jobs/{id}` for `field_report_id`. Validate classified non-self comparisons. `GET /api/field-reports/{id}` reads stored reports. Save numerical/deterministic content before optional generation; LLM failure preserves this report and sets failed job/error. Disk-save failure must still terminate the job.
- `GET /api/field-reports/{id}/export?kind=report|data|papers` produces UTF-8 BOM CSV with spreadsheet-formula protection. Report CSV contains narrative, numeric observations, evidence IDs and caveats. Data CSV contains annual/forecast rows plus typed JSON Pointer paths for all aggregate metadata including complete `export_data`. Paper CSV preserves full source text and bibliographic metadata. Generated CSVs contain report/analysis IDs.
- `GET /api/llm/status` returns local backend/model availability plus OpenAI configuration from the request's browser settings, default provider none. `app/field_llm.py` supports Ollama (`/api/tags`, `/api/show`, `/api/chat`), local OpenAI-compatible servers (`/models`, `/chat/completions`), and the official OpenAI Responses API with strict structured output and `store=False`. Local URLs are loopback only, redirects/proxy environment disabled; detectable Ollama cloud models are rejected. Compatible servers must be configured for local inference by the user.
- Generation is opt-in. Payload contains comparison metrics plus at most 8 papers per field, title/1400-character abstract excerpt/author names/explicit affiliations. Method snippets and evidence IDs are restricted to supplied papers. Validate output schema and reject unknown evidence IDs; accept narrative only, never replace metrics. Unavailable LLMs leave deterministic reports fully usable. GUI discloses data sent to OpenAI.

## Foresight numeric warnings (2026-09-14)
- Numeric/sign/recognized-unit mismatches in complete structured foresight facts and critiques are nonfatal. Preserve generated statements, headlines, section titles/text and caveats. Persist `validation:{status:passed|warning,warnings:[{code:numeric_mismatch,location,message,unmatched_numbers,unmatched_quantities:[{value,unit}]}]}` on facts/narrative/sections. Narrative aggregates fact warnings at `facts/<id>/statement`; fact verification is `quote_checked_numeric_warning` when needed.
- Only original quoted source text and immutable numerical metrics establish numeric evidence; generated statements cannot whitelist their own unsupported numbers. Source quote/position mismatches, unknown evidence IDs, invalid schema and incomplete JSON remain errors.
- Commentary jobs with numeric warnings complete and save a new revision with `validation_status:warning`, never overwrite growth/readiness metrics, and show an amber warning icon above the prose and on affected sections/facts. Details identify locations and unmatched tokens. Reopened saved versions, PDF and CSV/JSON retain the warning. No false all-passed wording on warned output. A warning is a mechanical mismatch, not proof of factual falsity.
- Previously rejected prose was not persisted and needs regeneration. The browser's connection settings remain untouched.

## Topic models extension (v1.3)
- Analysis options: `embedding:tfidf|sbert|transformer`, `sbert_model:null|mpnet|multilingual_minilm`, `topic_model:kmeans|nmf|lda|bertopic`, `min_topic_size:2..100` (default 5). Existing options remain. New `sbert` defaults to all-mpnet-base-v2; multilingual preset uses paraphrase-multilingual-MiniLM-L12-v2. Legacy `transformer` preserves ATLAS_EMBEDDING_MODEL with multilingual default. Explicit SBERT presets do not use environment overrides.
- K-means accepts TF-IDF or SBERT. NMF/LDA require the lexical `tfidf` mode; LDA rebuilds integer CountVectorizer counts rather than fitting TF-IDF. BERTopic requires SBERT/legacy Transformer and optional requirements-topics.txt. Invalid combinations or missing dependencies raise readable errors; no silent fallback.
- `app/topic_models.py`: `fit_topic_model(documents, tfidf, terms, embeddings, method, n_topics, min_topic_size=5)` returns compact nonnegative labels, map_matrix, model-derived topic_keywords, JSON-safe details, outlier_label, membership, warnings. NMF/LDA retain component mixtures for maps and use dominant assignment for paper counts. Membership is not classification accuracy.
- BERTopic uses supplied normalized embeddings, UMAP, HDBSCAN and c-TF-IDF. n_topics is a reduction target, not a promised count. Preserve HDBSCAN -1 as a compact unclassified group. Empty vocabulary and information-insufficient papers remain unclassified. Never discard or arbitrarily reassign them.
- Topic/paper `is_outlier` flags identify unclassified records. Outlier topic status is `unclassified`, score 0, forecast empty. `summary.topics` counts classified groups only. All papers remain in corpus totals/maps/evidence; exclude unclassified groups from hot/emerging rankings, theme forecasts, LLM topic evidence, and monthly rising classifications. Monthly count-only rows remain available.
- Meta adds `topic_model`, `topic_model_details`, `embedding_model_preset`, `sbert_model`, `min_topic_size`, `unclassified_papers`, `classified_topics`, `map_representation:tfidf|sbert_embeddings|nmf_topic_distribution|lda_topic_distribution`. NMF/LDA maps and edges use topic distributions; BERTopic display map uses SBERT with separate t-SNE, not its internal UMAP coordinates.
- Status adds `sbert_models:[{id,model_id,label,language}]` and `topic_models:[{id,label,available}]`. GUI separates embedding and topic method, locks compatible inputs, and displays actual methods plus gray unclassified points. CSV/HTML/JSON retain model metadata and unclassified counts.

## Monthly exploration extension (v1.2)
- Paper date fields: `publication_date` is ISO `YYYY-MM-DD`, `YYYY-MM`, or empty; `date_precision` is `day|month|year|unknown`; `date_source` identifies the source field. Never synthesize months for year-only records. Existing valid date takes precedence during merging; supplement only from a compatible publication year. `app/dates.py` centralizes normalization.
- Discovery accepts optional paired `start_month/end_month` (YYYY-MM, maximum 24 months, year fields must match). Monthly queries use real bounds and per-month ranked quotas. Reports add `month_coverage:[{month,total,imported,allocated}]`, `sampling=per_month_relevance_top`, and `date_pipeline_version=2`. Year mode retains `per_year_relevance_top`. Cache entries without date pipeline version 2 are re-fetched.
- Analysis accepts `window_months:1|3|6` (default 3), `anchor_month:null|YYYY-MM`. Default anchor is latest complete month bounded by selected end year, never the last document date. Current/future months are not valid anchors. Internal `observed_months` represents searched periods: union repeated chunks of one provider/query, intersection across distinct search populations. Missing comparison months prevent a growth claim; unknown CSV coverage is disclosed.
- `frontiers.monthly`: `{available,reason,reason_label,anchor_month,latest_complete_month,window_months,stale,date_coverage,dated_papers,undated_papers,months:[{month,count,observed}],recent_months,baseline_months,recent_total,baseline_total,topics,warnings}`. Topic rows: `{topic_id,label,recent_count,baseline_count,delta,growth_pct,share_change_pp,status,series,evidence_ids}`. Status is `rising|new|stable|declining|insufficient`. Previous zero means null growth. Aggregate empty windows and missing dates prevent classification. All counts refer to the imported corpus with usable dates.
- `frontiers.sparse`: `{candidates,terms,criteria,method,warnings,corpus_papers}`. Candidate `{id,term_a,term_b,count_a,count_b,observed,expected,ratio,score,topic_a,topic_b,evidence_a,evidence_b,joint_evidence_ids}`. Exact normalized phrase matching on all selected papers, not map sample. Support >=3 per term, nA*nB/N >=2, joint <=2 and joint <0.5*reference. Max 24 terms and 12 pairs. Reference count assumes independence; score is a ranking heuristic. No novelty, plausibility, causality, or statistical significance inference.
- `frontiers.scope` carries `{sampled,providers,corpus_papers}`. Monthly and sparse screens disclose capped sampling and evidence limitations. Sparse candidates highlight existing evidence points only; t-SNE empty coordinates or density never imply a research gap.
- Topic CSV appends monthly counts, anchor, window, growth/share difference and status. HTML includes monthly and sparse sections; JSON contains all evidence IDs and scope. Old results without frontiers still export.

## Analysis result JSON
`meta`: `{start_year,end_year,years:[int],embedding,embedding_model,forecast_horizon,paper_count,abstract_coverage,citation_history_coverage,warnings:[str],is_demo:false}`

`summary`: `{papers:int,authors:int,keywords:int,citations:int,topics:int,emerging_topics:int,growth_pct:float|null}`

`timeline`: `[{year:int,papers:int,citations:int,annual_citations:int|null}]` citations = cumulative citations grouped by PUBLICATION year. Annual_citations = available annual event counts; disclose incomplete coverage.

`topics`: `[{id:str,label:str,keywords:[str],count:int,citations:int,growth_pct:float,share:float,score:float,status:'hot'|'emerging'|'stable'|'declining',color:str,series:[{year:int,count:int,share:float}],forecast:[{year:int,value:float,lower:float,upper:float}],backtest:{mae:float|null,baseline_mae:float|null,folds:int},evidence_ids:[str],explanation:str}]` score heuristic 0–100, share 0–100, forecast on annual paper count; uncertainty is exploratory scenario band, not calibrated probability.

`keywords`: `[{term:str,count:int,growth_pct:float,series:[{year:int,count:int}],topic_id:str}]`

`network`: `{nodes:[{id:str,label:str,count:int,citations:int,topic_id:str,x:float,y:float,years:[int]}],edges:[{source:str,target:str,weight:int}],truncated:bool}` top coauthor nodes, coordinates normalized 0–1.

`map`: `{nodes:[{id:str,label:str,topic_id:str,year:int,citations:int,x:float,y:float}],edges:[{source:str,target:str,weight:float}],method:str,truncated:bool}` semantic paper map coordinates normalized 0–1. nearest-neighbor semantic edges, explicitly not citations.

`papers`: filtered normalized papers extended `{topic_id:str}`.

`methodology`: `[str]` descriptions and limits.

## HTTP API (root implements)
- `GET /api/status` -> `{llm_configured, transformer_available, datasets:[{id,name,paper_count,is_demo,created_at}], default_start_year,default_end_year}`
- `POST /api/demo` JSON optional `{}` -> `{dataset:{id,name,paper_count,is_demo,created_at}}`
- `POST /api/import` multipart `file` CSV -> `{dataset:{...},report:{...}}`
- `POST /api/datasets/{id}/citations` multipart `file` CSV -> `{dataset:{...},report:{...}}`
- `POST /api/analyze` JSON `{dataset_id,start_year,end_year,n_topics,embedding,horizon}` -> `{job_id}`
- `GET /api/jobs/{job_id}` -> `{status:'queued'|'running'|'completed'|'failed',stage:str,result_id?:str,error?:str}`
- `GET /api/results/{id}` -> above analysis object with extra `{id,dataset_id,dataset_name}`
- `POST /api/insights` JSON `{result_id,topic_id?:str,question?:str,use_llm:false}` -> `{mode:'local'|'llm',headline:str,findings:[str],hypotheses:[str],caveats:[str],evidence_ids:[str],model?:str}`. use_llm true is explicit external request; UI discloses that topic metrics + selected titles/abstracts are sent to OpenAI. Keys come from the browser connection header.
- `GET /api/results/{id}/export?format=json|csv|html` download full analysis, topic table, self-contained printable report respectively.
- `GET /api/demo.csv` download demonstration source CSV.
- `GET /api/citation-template.csv` download long-form citation sample (EID,Year,Citations).
- JSON error body `{detail:str}`. UI must handle errors, loading, no data, polling; never hardcode analytical values. On first load create/load demo and run analysis, badge prominently '合成デモデータ'. Dataset upload and analysis controls available in modal or side panel. Connection settings have a separate browser-storage form accessible from analysis settings and the field report.

Data constraints: import max 20 MB, max 10000 records local prototype. Default excludes unfinished current calendar year; if user includes current year warn. Future forecasts must use publication count histories only; rolling origin score uses historical count series with fixed retrospective topic labels, disclose that full topic extraction is retrospective. LLM adds hypotheses grounded in measured evidence, does not replace numerical forecasts or claim foresight.
