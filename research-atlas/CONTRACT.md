# Research Atlas implementation contract

Local FastAPI + plain HTML/CSS/JS application. All labels/help are Japanese with restrained English design accents. No external frontend CDN. Python does numerical analysis. `data/` persisted locally and ignored by git.

## Resumable publication-date enrichment (v2.4)

- `app/publication_date_sources.py` exposes `extract_doi(paper)` and the thread-safe context manager `CrossrefDateClient(contact_email='', stop_event=None)`. Prefer the explicit DOI; otherwise accept one unambiguous DOI in `external_url`, `source_link` or supported Link fields, including DOI resolver/publisher paths and an explicit Scopus `doi=` parameter. Preserve imported raw `source_link` independently of the safe external URL. Never fetch an arbitrary imported URL, follow redirects, scrape an authenticated Scopus page, or infer a DOI from an EID-only link. Query only the fixed `https://api.crossref.org/works/<URL-encoded DOI>` endpoint and require exact normalized response-DOI equality.
- Publication observations keep `{doi,status:found|not_found|error,provider:'crossref',source_url,fetched_at,candidates:[{date,precision,kind}],excluded_candidates,retryable,error_kind?}`. Accept only `published-online`, `published-print`, `published`, and `issued` with valid explicit date parts. Preserve `YYYY`, `YYYY-MM`, or `YYYY-MM-DD` precision; never synthesize a month/day. Registration/creation, deposit/update, indexing and acceptance dates are not publication dates. Future candidates are separate exclusions, never applicable dates. Bound streamed responses to 2 MiB and sanitize transport errors; incomplete or mismatched metadata cannot silently become a date.
- All enrichment clients share an adaptive host gate. Single-DOI public defaults are 5 requests/second with concurrency1; optional valid contact email uses polite defaults of10/second with concurrency3. Honor lower `x-rate-limit-limit`, `x-rate-limit-interval`, `x-concurrency-limit` values and `Retry-After`; requests never bypass these limits by splitting jobs. Transient retries are bounded to three total attempts. Long waits return a deferred result, and rate-limited/blocked jobs persist progress and a `retry_at` instead of sleeping for minutes or losing completed work. Cancellation checks also apply while waiting for admission and reading responses. Fixed API requests use the existing request-scoped browser Proxy settings; no environment routing or credential persistence is introduced.
- Throughput limits are not a completion-time SLA. For 20,000 uncached unique DOIs, 20,000/5 = 66 minutes40 seconds and 20,000/10 = 33 minutes20 seconds are theoretical rate-only lower bounds. Response latency, concurrency, failures, provider load and retries can make the actual duration longer. Sources: [Crossref access and authentication](https://www.crossref.org/documentation/retrieve-metadata/rest-api/access-and-authentication/) and [July2026 single-record/list rate-limit update](https://community.crossref.org/t/refining-rest-api-limits-for-improved-stability-and-reliability/16137).
- `app/publication_date_enrichment.py` owns `data/publication_dates.sqlite`, separate from source dataset/results storage. Jobs retain the source dataset ID, target, original per-paper date metadata, unique DOI work items, append-only observations, cache references and application snapshots. Reuse successful metadata for30 days and not-found/no-date metadata for7 days; retryable errors remain pending. Duplicate papers sharing a DOI use one request. Counts distinguish eligible papers, unique/processed/pending/found/not-found/error/cached DOIs and papers without a resolvable DOI. No source dataset or saved analysis is changed during retrieval.
- Requests choose `target:missing_month|missing_day|all` (default `missing_month`) and strict `batch_size:1..20000` (default500). Each run processes at most that many pending uncached unique DOI items, then pauses if work remains. Resume is manual, not a scheduler or a request for unattended future work. Closing the UI leaves the current batch running; pause stops further dispatch and may await an active request. Restart recovery converts abandoned running/preparing jobs to paused state; saved successful observations survive. Only one enrichment job runs at a time in this process. Same-process worker submissions propagate the browser request context. Contact email is request-only and is absent from the SQLite schema, observations, exports, logs and `.env`; titles/abstracts are not sent to this API.
- Date preview/application accepts `policy:same_year|online_first|print_first` (default `same_year`) and strict `overwrite_existing:boolean` (defaultfalse). `same_year` filters to the original publication year, prefers finer precision, then online/print/published/issued candidates. `online_first` and `print_first` prioritize their named event, then the other event, published and issued; these policies can change a year-only record's year. Existing explicit month/day values remain unless a compatible finer date fills a missing day, or overwrite is explicitly selected. Keep source/candidate disagreements in the audit even when one candidate is selected. Year-only candidates remain observations and never fill a month/day.
- Application freezes the exact observation IDs into a snapshot and creates a new derived dataset with parent dataset ID, policy, counts and `date_enrichment` provenance on changed papers. Preserve original year/date/precision/source in that provenance. Original papers, citation values and prior analyses remain unchanged; later resume/retrieval cannot change an already-created derived dataset. Reanalysis of the derived dataset is required for month/quarter time layers, centroid movement or annual counts to reflect supplemented dates. A partially retrieved job may be applied without discarding unresolved papers.
- The UI exposes source date coverage, batch size, pause/resume, saved job history, candidate definitions, discrepancies, adoption preview and CSV download. The evidence CSV is separate from paper-analysis exports; it includes original identifiers/dates, every candidate, precision/kind, source URL/time, policy, proposal, conflict/reason and excluded candidates. Use UTF-8 BOM and spreadsheet-formula protection. Crossref coverage is incomplete; absence of a registered date does not establish absence of a publication. There is no DataCite fallback or general publisher-page crawler in this release.

## Movement evidence selection (v2.3.2)

- Movement requests and annual optional transitions accept strict `papers_per_period` integers1..20 (default6), `selection_method` centroid/diverse/cited/recent (defaultcentroid), and boolean `abstract_only` (defaultfalse). Single-centroid/yearly paper-review chapters retain their original maximum6 and prompts. Controls affect evidence only, never measured centers/counts/tests.
- Unchanged defaults preserve saved movement representatives. Customized selection uses the original sample representation and displayed paper IDs, or the full-corpus cached representation and all period-topic candidate records. Never choose20 from the old capped6 ID lists. One selection context caches compact metadata/vectors and period groups across annual comparisons.
- Centroid ranking uses cosine distance to the mean of all valid original vectors before abstract filtering, independent of map coordinates. Diversity uses deterministic MMR (centrality .65, nonnegative similarity redundancy .35), starts with the nearest paper, and never allocates an N-by-N matrix. Citation ranking uses retrieved cumulative counts, unknown after known0, without age correction. Recent ranking respects date precision and does not fabricate January1 for year-only records. Stable ID tie breaks apply.
- Save requested selection, candidate/eligible/selected counts, ordered IDs, source representation, rank, distance and missingness/selection warnings. Preserve priority when resolving IDs to abstracts. CSV includes the audit; UI distinguishes this selection from papers actually sent after local context adaptation. Customized comparisons without substantive abstracts on both sides retain measurements and clearly skip/fail LLM content comparison, while other annual chapters remain available.
- Keep full audit metadata outside the LLM payload. The compact input-summary description and ordered evidence convey selection. Capacity adaptation prunes movement evidence_before/evidence_after as well as evidence_ids, so omitted references cannot masquerade as submitted sources. Numerical validation recognizes citation counts and selection metrics only from supplied, cited papers. Existing prompt constants and browser-owned connection settings remain unchanged.

## Bounded local LLM inputs

- The shared `field_llm.structured_output` gateway budgets local requests for field/neighbor reports, centroid paper critiques, movement interpretations, each annual chapter/transition and both foresight extraction/critique stages. Existing system/prompt constants and OpenAI behavior are unchanged. Whole-corpus numerical analysis does not imply whole-corpus LLM input.
- Browser-owned `local.context_window` is null/automatic by default, accepts integers2048..262144, and `local.max_output_tokens` defaults to4000 with bounds512..32768. No cross-field rejection: effective output is `min(requested,max(512,window//3))`. Record requested and effective output separately. Read loaded/configured server context when available; unknown compatible servers use8192 and unknown Ollama servers use4096. Explicit browser values cannot exceed a detected server limit; a known Ollama model ceiling also clamps the request. Do not treat a theoretical model maximum as its active capacity or silently enlarge an unknown loaded context. User configuration must match the server's actual loaded limit.
- `app/llm_context.py` estimates ASCII at one token per three characters (rounded up), non-ASCII at its UTF-8 byte length. Include serialized payload, system instructions, schema, reserved output and512 safety tokens. This conservative estimate is not a model-tokenizer measurement. No tokenizer/model download is introduced. If required context cannot fit, fail clearly before generation while preserving computed analysis.
- Deep-copy input before adapting it. Shorten abstract beginnings/conclusions together with omission markers and source ranges, then reduce lower-ranked papers across period/topic groups while preserving each group's final substantive evidence paper. Missing abstracts remain missing. Selected excerpt IDs represent indivisible original quotes; completed fact objects retain intact quote/provenance/ID fields and can only be dropped as units. Do not alter numerical metrics, period metadata or original source records to fit the request.
- Retry at most twice after recognized server input-context overflow, reducing the next input budget and honoring a server-reported smaller limit. Ordinary authentication, network, malformed/incomplete output, output token cutoff and other failures are not blanket retry triggers. Generation progress can include a safe `event.stage` message for input reduction.
- Optional gateway `input_context` returns the last prepared actual payload and safe budget metadata, including on failure. Store estimates, limit/source, requested/effective output, omitted IDs, reduction state and attempt counts, never connection secrets. Field/landscape validators use actual sent evidence; foresight filters extraction IDs against actual sent excerpts, restores offsets/hash against original source abstracts and validates critique IDs only against actual sent facts. Omitted IDs cannot become verified citations. Foresight input hashes use the actual submitted payload.
- Reports expose input accounting and excerpt limitations. CSV/JSON exports retain the corresponding stored audit; commentary caveats carry reduction notices into supported PDF/print outputs. Foresight `candidate.llm_input` has separate `extraction`/`critique` safe metadata, and API failure revisions retain available audit without mutating the prior assessment. Annual chapters preserve their own input audits and failures independently.
- Old `research-atlas.connections.v1` records gain missing token defaults in memory without losing credentials or rewriting storage until explicit Save. Browser credentials/settings remain request-scoped, with no environment fallback or `.env` persistence.

## Interactive coauthor exploration (v2.3)

- The author UI and POST /api/author-networks default to institution grouping; conservative author identity and explicit author-affiliation rules remain unchanged. Missing institutions stay unknown. Synthetic demo authors have explicitly fictional institutions.
- Compute six metrics on the full undirected induced graph of the publication-count-ranked display authors (currently max120), before the240edge drawing cap: degree, strength, normalized unweighted Brandes betweenness, weighted PageRank(alpha0.85 with uniform teleportation/dangling redistribution), unweighted local_clustering, institution_bridge(distinct known external primary institutions among direct coauthors). Unknown own institution yields null bridge count; unknown neighbors are excluded. The primary institution is the most frequent explicit affiliation in the corpus, not a current employment or migration inference.
- Each displayed node has metrics, metrics_computed:true, complete neighbor_ids and neighbor_weights(author ID to coauthored-paper count). This compact adjacency survives large-store display trimming so selected edges can be restored without relying on export_data. Outside-population authors retain metrics with null values and metrics_computed:false. Preserve nulls through JSON and CSV, never zero-fill uncomputed metrics. network.metric_definitions and metrics_scope document formulas, population, weighting, convergence and limits.
- UI selects metric and highlighted candidate count without recomputing metrics on search or cluster filters. Betweenness is the initial metric. Show metric meaning, tied ranks and calculation scope; high local transitivity means cohesive neighbors, not a bridge. Pan/zoom, node dragging and reset affect display only. Node selection reveals its direct neighbors; dragging must not accidentally open details. Preserve existing evidence/detail dialogs, grouping, search and CSV exports; remove interaction listeners on rerender/view change.
- CSV adds six explicit metric columns, computed state and true neighbor IDs. Large indexed storage preserves metrics and scope in display payloads and full exports. No LLM prompt or connection setting changes.

## Annual landscape report (v2.2)

Existing centroid and movement LLM instruction strings are unchanged; each child uses the existing excerpt preparation and final-answer validation. No synthesized all-year LLM conclusion is presented as generated output.
- Each annual row retains topic count, same-year/same-scope denominator, fractional share, characteristic terms and coverage state. A topic absent from an observed corpus year has count/share0; a year with no corpus observations has no defined share. Missing vectors/abstracts never produce invented content. Sample/full scope is explicit.
- Year chapters are existing centroid reports. Optional transitions are only existing landscape movements with both endpoints in the selected range; gap metadata and uncertainty are retained. The overall overview is deterministic, distinguishes endpoint changes from a monotonic trend, and does not call corpus growth global popularity.
- POST /api/landscape-annual-reports creates a queued request-context-owned job. GET /api/landscape-annual-reports/{id} returns initial, partial or completed state; /export emits formula-safe UTF-8 CSV. Cancellation stops subsequent chapter calls, retains completed chapters, and does not imply immediate interruption of an in-flight generation. API/proxy settings remain browser-only and are never copied into stored reports.
- Frontend shows planned call count before generation, chronological chapters and count/share graphics, known paper links, exact input excerpts and non-blocking verification warnings. Stale responses cannot replace another topic/result/range. Report-only browser printing supports Save as PDF; it is not a server-generated PDF endpoint.

## Citation time atlas (v2.1)

- `citation-flow` is a separate navigation view from the technology landscape and citation count charts. `static/citation-flow.js` mounts with the app's browser-aware API helper, disposes animation work on navigation, and uses no external libraries or settings storage. The root app calls unmount before replacing its content.
- `GET /api/results/{result_id}/citation-flow?interval=year|quarter|month&topic_id=all|<topic-id>` computes all selected source papers against the saved full analysis corpus. The two content centers use the shared L2-normalized document representation and exact PCA for a fixed XY display across all publication periods. Reference metadata is never fetched from an external service as a side effect.
- Current center is the equal-weight mean of all nonzero current-period source vectors. For the reference-foundation center, each source with a valid vector and at least one eligible target contributes the mean of its valid, uniquely resolved, strictly older reference vectors. These per-source means are averaged equally. A paired-current center uses exactly the same source population; the reported cosine distance compares it with the foundation in document space. It is not the distance between two drawn symbols or a causal/importance score.
- References resolve only normalized DOI/provider identifiers and saved aliases, never titles, local IDs, embedding proximity or total citation counts. Repeated source-target pairs, ambiguous/conflicting identifiers, self-references, future targets and uncertain date ordering are excluded. A year/month-only date is an interval, so it cannot establish within-interval chronology. Periods with missing dates are not silently imputed.
- Display is bounded to 240 papers/480 citation edges; analytical counts/centroids use all eligible records. Every drawn edge has both drawn endpoints and points **citing new paper → cited older paper**. Reference centers are placed on the citing cohort's plane; reference paper nodes remain on their actual publication-time planes. Drawing sample limits, reference availability, matching coverage and exclusion reasons remain visible in the response.
- Temporal plane expansion, moving light on citation edges, pause/replay, layer spacing and orbit controls respect reduced-motion and stop when the view is inactive. Animation never changes analytical coordinates or reference relationships.
- `/citation-flow/export?format=csv|json` exports the current computed view, including full-cohort summaries and the bounded display graph, without LLM calls or saving credentials. CSV uses typed JSON Pointer leaves, UTF-8 BOM and formula protection. Exports do not claim to contain every underlying citation edge.

## Landscape relief and contours

- `GET /api/results/{result_id}/terrain` reads an existing saved map, then returns `{version:1,grid:{width:49,height:33,values:[row-major density]},contours:[{level,paths:[[[x,y],...],...]}],node_heights:{paper_id:height},meta}` without modifying results. Empty maps return zero grid/no contours. Cache bounded32 by normalized paper IDs/coordinates, with response copies.
- Python `app/map_terrain.py` uses equal-weight Gaussian KDE on at most400 projected papers, bandwidth0.075 in normalized coordinates. Density is divided by its grid maximum, not total corpus size or citations. Marching squares with a saddle decider produces eight levels0.12..0.96; closed paths repeat their first point and boundary paths remain open. Node heights use bilinear grid sampling; the drawing approximates the surface with triangles.
- `static/map-terrain.js` renders inert SVG terrain and shared flat/relief projection. `static/landscape.js` integrates existing clickable paper nodes and topic labels, live height/contour/mode controls, scoped async loading/retry, bounded8-result browser-memory cache and retained zoom. Density is requested once per result, not on every display adjustment. Both overview and technical map use the same data. Browser connection settings are unchanged.
- Height is relative visual density in a 2-D projection, not an independent 3-D embedding, forecast, maturity, research scarcity or importance score. Existing maximum400 display sampling limitations apply. Highlighting a topic/recent papers never changes the density population.

## Content exploration and Rocchio extension (v1.6)

- The new `有望領域` tab initializes candidates from classified existing topics, retaining all papers but excluding unclassified topics from recommendations. It presents initial-cohort annual descriptions, content evidence, retrieval recommendations, feedback, query previews, round history, optional commentary, and PDF/CSV/JSON exports. It does not implement a trained future-growth forecast or predict commercialization probability/TRL.
- `app/foresight.py`: `build_assessment(result)->dict`; `refine_assessment(assessment,candidate_id,feedback,incoming_papers=None,embedding='tfidf')->dict`. Inputs remain unchanged; the core makes no external retrieval/LLM calls. Assessment includes `schema_version`, `result_id`, `dataset_id`, `meta`, `papers`, `candidates`, `rounds`, `feedback`, `retrieval_space`, `warnings`. Saved versions add `id`, `parent_id`, `revision`, `created_at`, `numeric_hash` under `data/assessments/`.
- Candidate IDs match topic IDs. Each retains `original_query`, `seed_terms`, `seed_paper_ids`, `seed_count`; updated `terms`, `paper_ids`, `provisional_paper_ids`, `count`, `growth`, `readiness`, `evidence`, `recommendations`, `retrieval`, `stance_feedback`, and deterministic `commentary` describe exploration. Automated evidence IDs identify fragments; each fragment has its own `paper_id`. Do not confuse fact IDs with bibliographic IDs.
- Rocchio uses a fixed original query, cumulative candidate/paper feedback with latest explicit judgement, coefficients original 1.0 / relevant mean 0.75 / explicit irrelevant mean -0.25 / provisional relevant mean 0.10. Support/counterevidence is a separate attribute and never determines the subtraction sign. Pseudo negatives cannot subtract or overwrite explicit feedback. An update is reduced when original-query cosine would fall below 0.80. TF-IDF clips negative coordinates and freezes the initial vocabulary/IDF; English words/bigrams and Japanese character 2/3-grams are lexical matching, not synonym resolution.
- Initial assessment uses TF-IDF; refinement optionally uses locally cached SBERT with existing token-window pooling. No model download or silent fallback occurs in exploration. Relevance/distance are cosine-based. Recommendations require positive similarity and original-query cosine >=0.04; up to 300 papers are reranked with an explicit shared-author penalty and 30 displayed. This is retrieval ranking, not a promise of technical value or proof of team independence. Up to 20 high-similarity retrieved papers may become provisional evidence without changing original topic assignments.
- `growth.series` uses the frozen initial paper/year snapshot and seed membership; incoming retrieval cannot rewrite its counts or denominator. Growth is descriptive of the initial imported corpus only. Single-year data, capped samples, synthetic/test input, absent comparison periods, or adaptive additions withhold the growth decision. All candidates retain `forecast=[]`, `forecast_available=false` and an explicit unimplemented-model reason, regardless of existing result forecasts.
- `readiness.evidence_coverage_score` is the percentage of six dimensions with an eligible abstract mention: performance, reproducibility/validation, real environment/prototype, scale/manufacture, durability/safety, cost/resources. It is not a maturity score, official TRL, or success probability. `stage='unassessed'`; missing evidence remains unknown, not failed. Generated/test abstracts are excluded. Full candidate-level paper counts accompany at most 120 fragments with exact character offsets, abstract hash, dimension, numeric mentions and heuristic stance; attribution and scientific meaning remain unverified.
- `app/foresight_sources.py` owns query construction and external retrieval. Query previews retain the original seed group plus updated terms. Europe PMC/arXiv/Crossref use public adapters; Scopus Search uses `ELSEVIER_API_KEY` (alias `SCOPUS_API_KEY`) and optional `ELSEVIER_INSTTOKEN` only in authentication headers. Configured availability is not verified entitlement. COMPLETE may fall back to STANDARD with missing-abstract warnings. Search never fabricates reference lists or annual citation histories. All retrieval reports retain actual queries, dates, per-year coverage, source provenance and adaptive-sampling limitations. Existing `merge_papers` checks the final 10,000-paper limit after deduplication and preserves citation-source separation.
- Initial public search queries are retained as a portable Boolean tree (words/phrases/AND/OR/parentheses), unioned across initial sources, then intersected with candidate terms. Unsupported field/NOT/wildcard syntax fails explicitly. All providers apply the initial condition again to visible title/abstract/keywords; record API retrieval count separately from accepted count and exclusions. Missing abstracts, abbreviations and synonyms can produce conservative false negatives. Round-generated queries cannot replace the initial scope.
- `POST /api/assessments {result_id}` starts a job; poll `/api/jobs/{id}` for `assessment_id`. `GET /api/assessments?result_id=...` lists saved versions; `GET /api/assessments/{id}` reads one. `GET /api/assessments/{id}/queries?candidate_id=...` previews queries without retrieval. `GET /api/foresight/status` exposes configured providers, local/OpenAI availability, embedding dependencies and PDF availability without credentials.
- `/?result_id=...&assessment_id=...&view=foresight` restores a saved result and assessment via API, validates matching ownership and the original dataset, and restores analysis options without recomputation. Missing/mismatched identifiers produce a visible error; stale responses cannot change state or URL. New analysis clears old restore identifiers. Links depend on this local server and its persisted data.
- `POST /api/assessments/{id}/explore` accepts `{candidate_id,mode:local|external,provider:europepmc|arxiv|crossref|scopus,max_rounds:1..3,limit:20..100,embedding:tfidf|sbert,feedback:[{paper_id,relevance:relevant|irrelevant|unknown|unjudged}]}` with <=100 feedback items. The public feedback UI/API judges relevance only; internal evidence stance is distinct. Each successful round saves a new immutable version. External pre-query refinement and post-retrieval recomputation use the same parent to record one update per round. Unchanged top recommendations with no additions stop early; failures retain the latest saved version. Synthetic/test assessments reject external real-paper mixing.
- `POST /api/assessments/{id}/commentaries {candidate_id,provider:none|local|openai,model?}` optionally runs two-stage extraction then critique using existing local/Ollama/OpenAI connection rules. Send <=12 papers (title <=350 characters, abstract prefix <=2400), <=32 extracted facts and bounded scope metadata. Synthetic/test assessments and missing/test abstracts cannot supply LLM effect evidence. Check exact contiguous quotes, supplied paper/fact IDs, supported numeric tokens/signs/recognized units and required support/counter/outlook/next_steps sections; headlines, titles and caveats receive numeric checks too. These are mechanical checks, not semantic/causal/scientific verification. Numerical growth/readiness blocks are immutable; model/prompt/input hashes and generated facts are versioned separately. Refinement removes stale generated narratives/facts.
- `GET /api/assessments/{id}/export?format=json|csv|pdf&candidate_id=...` renders a saved snapshot without LLM regeneration. JSON retains structure; UTF-8 BOM CSV flattens JSON Pointer paths, types and values with formula protection; Japanese PDF uses reportlab and an embedded TrueType font (`ATLAS_PDF_FONT` override). Failed optional generation does not prevent numerical exports. Dataset switches and stale asynchronous responses cannot replace the active assessment in the GUI.

## Scopus CSV compatibility repair (2026-09-14)

- Incomplete full-name columns must not discard authors when short-name and ID lists align. Enrich by explicit embedded ID; do not guess the positions of incomplete names.
- A leading `[TEST SUMMARY; TITLE-BASED; JA]` is test metadata. Keep the raw abstract, remove only this prefix for text features and co-occurrence, flag the dataset as containing synthetic/test data. This marker does not prove bibliographic identities are fictional.
- Dataset summaries include initial analysis years: declared search scope first, otherwise observed CSV years, bounded to API limits. Importing papers applies them and clears a stale monthly anchor; citation-history additions retain selected conditions.
- A single selected calendar year has no comparable annual growth or publication forecast. Counts, maps, field reports and author networks remain available; unknown publication months remain unknown.
- For a corpus with no declared collection scope and only one actual publication year, the API derives `single_year_corpus=true`; expanding the selected years cannot reinstate growth/forecasts or inflate publication momentum. `meta.annual_comparison_available` explains availability to the GUI. Declared public-search windows retain observed zero years.
